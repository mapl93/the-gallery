## Overview

Testimonials presents a passive, container-responsive collection of verified attributed quotations with optional canonical Avatar composition.

The collection has an optional section title and a required native list. Each item relates a `blockquote` and external `figcaption` inside a `figure`. A visible author name is required; Avatar and author detail are optional and never replace that text identity.

## Usage Guidelines

<DoDont>
  <Do>Publish attributable testimonials whose wording and source have been verified.</Do>
  <Dont>Do not fabricate endorsements, obscure material edits, or turn passive testimony into an unexplained control.</Dont>
</DoDont>

Keep each quotation focused and preserve enough author detail for the endorsement to be understandable in context.

Omit records whose quote or visible author name is empty. If no valid record remains, omit Testimonials rather than rendering an empty list or section. Record verification, consent, moderation, source links, ordering and publication remain target responsibilities.

## Accessibility

- Use a native `ul`/`li` collection with `figure`, `blockquote` and external `figcaption`; no ARIA list roles are required.
- Keep the optional opening mark `aria-hidden`, target-localized or omitted.
- Keep every author name visible when Avatar is composed. Adjacent redundant images use `alt=""`; adjacent redundant initials are `aria-hidden`.
- Do not use HTML `cite` for a person's name; it represents the title of a creative work.
- Treat testimonial cards as passive content unless a separately contracted control is added.
- Use a title-labelled native section when a title exists and a neutral root when it does not.

Testimonials has no controlled state, keyboard model, motion or neutral runtime. Columns are private root-container composition rather than a public property. Web, Shopify, Webflow, React and future native targets own their records and source-verification lifecycle while preserving the same quotation boundary.
