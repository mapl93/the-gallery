## Overview

Finite, user-controlled native scroll-snap carousel with named slides, canonical Icon Button navigation, synchronized pagination, and a polite position status.

## Usage Guidelines

Slide gap, control inset, pagination spacing, dot size/active scale and track/dot
focus geometry are public tokens. Spacing factors multiply the shared spacing
base. Navigation composes Icon Button and exposes its existing size, icon,
border and focus tokens; it does not duplicate those values. Slide artwork,
content width and collection density remain consumer composition choices.

Studio's first-dot control moves the actual viewport. Selecting another dot,
direct scrolling and Reset keep viewport, current dot and status synchronized.
Navigation that becomes disabled at a finite bound moves focus to the track.

<DoDont>
  <Do>Use carousel for a small, finite set of related content that remains directly scrollable.</Do>
  <Dont>Don't hide essential content only inside a carousel or add autoplay, loop, or root-wide arrow interception without a new product decision.</Dont>
</DoDont>

## Accessibility

<Callout type="warning">
  v1 is user-controlled and finite. Autoplay would require an explicit pause control and a new accepted contract decision.
</Callout>

- Name the carousel region and expose every slide as a named group with its position in the set.
- Give previous, next, and dot controls accessible names and connect them to the track.
- Keep visible slide, `aria-current`, disabled bounds, and polite status synchronized after buttons, dots, touch, wheel, or native keyboard scrolling.
- Leave arrow keys with the focused scroll viewport or descendant content; do not intercept them at the carousel root.
- Use logical placement for RTL and remove authored smooth motion under reduced motion.
- All images must have descriptive `alt` text.
