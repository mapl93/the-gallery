## Overview

Pin Input captures one numeric verification code through real, independently
clickable and focusable native character inputs. It does not use a hidden
full-code field: every visible segment is a form owner.

## Presentation

Pin Input supports `default`, `error`, `success`, and `warning` validation families across every cell in the group.

## Usage Guidelines

<DoDont>
  <Do>Always pair form inputs with visible labels for accessibility.</Do>
  <Dont>Don't rely on placeholder text as the only label — it disappears on input.</Dont>
</DoDont>

## Accessibility

<Callout type="tip">
  Shared Web enhancement coordinates numeric typing, Backspace, logical arrows,
  paste, autofill distribution, filled state and reset across the same real
  fields. Verification, submission consequences and live result messages remain
  target-owned.
</Callout>

- Provide a visible group label for the full one-time-code input.
- Use `autocomplete="one-time-code"` when capturing verification codes.
- Keep every cell in normal Tab order, directly clickable and independently
  focusable. Logical arrows supplement rather than replace Tab.
- Give all ordered segments the same non-empty `name`. Static Web reconstructs
  the code with `new FormData(form).getAll(name).join('')`.
- Give every segment a localized positional accessible name and associate group
  guidance or validation with all segments.
- Do not add a hidden mirrored input, auto-submit on completion, or announce
  each keystroke.
