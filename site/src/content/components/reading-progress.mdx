## Overview

Reading Progress provides a fixed top-edge track and a target-controlled visual indicator. It does not define how reading progress is calculated, synchronized, or exposed to assistive technology.

The root uses `.reading-progress`; the required indicator slot uses `.reading-progress__bar`. The target supplies the measured width and any target-required state or semantics. The preview is intentionally visual and does not select a progressbar or decorative contract.

## Usage Guidelines

<DoDont>
  <Do>Treat the indicator as target-owned until a reading-state architecture is accepted.</Do>
  <Dont>Do not infer scroll calculation, synchronization, or live announcements from the width transition.</Dont>
</DoDont>

Whether Reading Progress and Table of Contents share a neutral reading-state enhancement or receive state independently from each target remains unresolved. Whether Reading Progress is semantic or decorative also remains unresolved.

## Accessibility

- Do not add `aria-live`, `role="status"`, or continuous scroll announcements without an accepted behavior decision.
- If a target chooses progressbar semantics, provide a useful accessible name and synchronized bounded values.
- If a target chooses a decorative indicator, keep it out of the accessibility tree.
- Keep the fixed visual track from intercepting pointer interaction with page content.
- Honor the canonical reduced-motion fallback.
