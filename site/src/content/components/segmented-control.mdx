## Overview

Native single-choice field with a visible group label and compact segmented presentation.

## Presentation

Segmented Control supports `default`, `error`, `success`, and `warning` validation families independently of native checkedness and required validity.

Studio and Exhibit expose the same public controls for legend gap, surface padding,
segment gap and padding, border width, typography, surfaces, selected shadow, focus
geometry, opacity and motion. The legend uses Input's shared label gap and weight.
Options retain at least 44px activation targets. Their inner radius follows the
surface radius minus its padding, clamped at zero; the inner focus inset follows
its width. These are derived relationships, not extra token defaults.

The existing 320px container query stacks options when their own available space
is narrow. It changes layout only; sizes and validation remain independent.
Default borders mix 60% of their field color with primary text; validation borders
use 70% and labels use 55%. Controls edit the named mix inputs, and hovering an
option preserves its validation text family. Forced colors uses system boundaries.

## Usage Guidelines

<DoDont>
  <Do>Use concise, mutually exclusive choices under one visible group label.</Do>
  <Dont>Don't use Segmented Control for tabs, multiple toggles, or independent actions.</Dont>
</DoDont>

## Accessibility

<Callout type="tip">
  Native radios own selection, Arrow/Space behavior, form value, validity, events, and reset.
</Callout>

- Preserve the native `fieldset`, visible `legend`, and same-name radio inputs.
- Keep checked state synchronized with the visible selected segment.
- Keep validation styling independent from checked and required-invalid state.
- Use Tabs when the options control tabpanels and Button/Toggle Group for actions.
