## Overview

Countdown calculates real remaining time toward one absolute future deadline. It owns clock projection, drift-safe scheduling, localization, the `running | expired` transition, retained zero values, and one optional expiry announcement. It does not decide whether the deadline represents a launch, offer, reservation, or any other domain event.

## Guidelines

<DoDont>
  <Do>Use a truthful absolute ISO deadline containing `Z` or an explicit numeric UTC offset.</Do>
  <Do>Choose a stable non-empty unit set. The default is days, hours, minutes, and seconds.</Do>
  <Do>Listen for `countdownexpire` or read `data-countdown-state` when the target needs to react.</Do>
  <Dont>Use a floating local date, reset the deadline per visitor, or create artificial scarcity.</Dont>
  <Dont>Announce every tick or make the timer itself focusable.</Dont>
  <Dont>Put redirect, price, purchase, replacement, persistence, or analytics policy inside Countdown.</Dont>
</DoDont>

## Behavior

`theme.js` validates `datetime`, reads the current clock, and recomputes the projection at the next boundary required by the smallest selected unit. Every connected instance shares one timeout. The timeout is removed while the document is hidden, then values are recomputed from the deadline on visibility, page-show, or window-focus recovery.

When the deadline is reached, every selected value remains visible at zero and the root exposes `data-countdown-state="expired"`. A single bubbling `countdownexpire` event reports the normalized deadline and expired state. Consumers can retain the component, hide it, replace it with contextual content, or execute a domain action without turning those reactions into Countdown properties.

An invalid, missing, date-only, or floating deadline never receives `role="timer"`. It shows the ordinary localized fallback text instead.

## Accessibility

- The runtime adds `role="timer"` only to a genuine updating counter.
- Visual segments are hidden from assistive technology; one complete locale-formatted remaining-time phrase names the timer.
- Timer retains its implicit `aria-live="off"`, so seconds are not announced repeatedly.
- Optional `expiredAnnouncement` content is written to a polite status node only once at the running-to-expired transition.
- Without JavaScript, the native `<time datetime>` and visible fallback preserve useful deadline information.

## Anatomy

| Part | Selector | Requirement |
| --- | --- | --- |
| Root | `.countdown` | Required native `<time>` with `datetime` and `data-countdown` |
| Fallback | `.countdown__fallback` | Required localized static deadline text |
| Display | `.countdown__display` | Required visual segment collection, hidden before valid enhancement |
| Item | `.countdown__item` | One stable wrapper per canonical unit |
| Segment | `.countdown__segment` | Visual value/unit pair |
| Number | `.countdown__number` | Runtime-owned locale-formatted value |
| Label | `.countdown__label` | Runtime-owned locale-formatted unit |
| Separator | `.countdown__separator` | Optional decorative separator |
| Announcement | `.countdown__announcement` | Optional one-shot polite expiry status |

## Public API

| Property | Type | Default | Meaning |
| --- | --- | --- | --- |
| `variant` | `default \| inline \| cards` | `default` | Visual treatment |
| `deadline` | absolute ISO date-time | required | Authoritative end point with timezone information |
| `units` | validated ordered preset | all four | Stable subset of days, hours, minutes, and seconds |
| `fallbackText` | localized string | required | Useful no-script/invalid-deadline statement |
| `expiredAnnouncement` | localized string | empty | Optional neutral phrase announced once at expiry |

Derived output is deliberately not a configurable input:

- `data-countdown-state="running|expired|invalid"`;
- one `countdownexpire` event per running-to-expired transition; and
- current localized values and accessible phrase.

## Target Translation

- Neutral Web uses canonical CSS and the shared progressive enhancer.
- Shopify can reuse the copied runtime only after a target-native surface supplies a truthful global deadline and placement; no merchant surface is assumed here.
- React and Angular adapters map deadline and unit props to the same neutral DOM/event contract rather than creating a second calculation model.
- Figma exposes static Running, Expired, Invalid and presentation examples without claiming a functioning clock.
- SwiftUI and Compose use native lifecycle scheduling while preserving the same deadline, units, derived state, zero, and expiry-event boundary.

## Human Review

The implementation is prepared for human stability review but remains `pilot`. Review Default, Inline, and Cards geometry; unit typography and separators; wrapping at narrow containers; long day counts; localized labels/digits; RTL; forced colors; and the retained-zero expired presentation before any `stable` promotion.
