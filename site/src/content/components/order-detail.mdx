## Overview

Order Detail is a passive section for one authoritative order. A required visible title labels the section; optional metadata, target-owned tracking through canonical Steps, and a read-only canonical Cart Line Item collection complete the composition.

## Presentation

`title` is the only required U5 property. A non-empty visible heading labels the native section with `aria-labelledby`; the target chooses the heading rank appropriate to the host page. The docs fixture uses `h2` inside Component Detail.

`meta` is semantic target-owned content. This fixture uses `time[datetime]`, but order numbers, date formatting, financial and fulfillment statuses, and any canonical Badge composition remain target responsibilities rather than U5 fields.

`tracking` is an optional ordered canonical Steps composition only when the provider supplies a trustworthy finite milestone model. The example stages and current projection are fixture data, not a Gallery-wide order-state taxonomy. When authoritative facts are non-linear or uncertain, omit Steps and render ordinary target-authored semantic status content. `lineItems` is an optional non-empty native collection of canonical Cart Line Item records with purchased quantity as text and no cart mutation controls.

The root establishes a named inline-size container. Header placement responds to U5 width; Steps and Cart Line Item keep their own responsive, semantic, token, forced-color, and reduced-motion behavior.

## Usage Guidelines

<DoDont>
  <Do>Map title, metadata, progress, and purchased items from the same authorized order, then compose canonical Steps and Cart Line Item.</Do>
  <Dont>Do not invent a universal stage sequence, duplicate stepper visuals, or expose cart mutation controls for purchased items.</Dont>
</DoDont>

- Omit the complete component when `title` is blank. Omit optional regions rather than rendering empty wrappers.
- Use Steps only when the provider supplies a trustworthy ordered sequence. Do not infer one from processing, fulfillment, shipment delivery, pickup, return, refund, partial, split, or cancellation state.
- Mark at most one canonical step current and retain non-color completed meaning.
- Use a real product destination only when it remains useful and authorized; otherwise render the canonical Cart Line Item title as text.
- Compose loading, redacted, unavailable, error, not-found, and expired-session UI outside passive U5.
- Keep addresses, payment details, totals, refunds, returns, actions, carrier data, and ETA content outside U5 until explicit semantic regions are accepted.

## Accessibility

- Protect or redact order data according to the target authentication and authorization context before rendering it.
- Label the section from its required visible title and preserve a context-correct heading hierarchy.
- Use native `time[datetime]` for date/time metadata when applicable.
- Keep tracking as a labelled native `ol/li` Steps composition with at most one `aria-current="step"`; do not add a custom role, roving focus, or arrow-key model.
- Keep completed/current meaning readable independently of connector or indicator color.
- Preserve native `ul/li` semantics for purchased items and normal Link Tab/Enter/modified activation for an available product destination.
- Do not make the complete order section or line-item row an additional interactive surface.
- Preserve DOM order title, metadata, tracking, items across container sizes, localization, RTL, zoom, forced colors, and reduced motion.

## Target Notes

- Target-controlled account views may project one authorized authoritative order through canonical U5. Platform-owned non-replaceable screens use documented native handoff without claiming U5 visual or functional parity.
- Shopify v1 uses the hosted current-account Order status page rather than a theme-owned clone. Customer Account extensions and headless API views are distinct target-controlled profiles; classic Liquid remains separately versioned compatibility.
- Protected loading, authorization/redaction, provider links, unavailable/not-found/error state, live updates, announcements and focus recovery remain with the owning target surface.
