## Overview

Checkout Progress is a passive checkout-context profile of canonical Steps. It
communicates target-supplied completed, current, and upcoming stages without
owning routing, navigation availability, visited state, validation gates,
persistence, announcements, or synchronization with checkout state.

## Presentation

The passive P4 wrapper contains the same labelled ordered list, items,
indicators, content, titles, optional descriptions, and status text as canonical
Steps. Wide containers retain the horizontal Steps presentation. Narrow P4
containers stack items and hide decorative connectors without changing DOM
order or using private Steps geometry.

The artwork exposes completion with a visible check and visually hidden state
text, places `aria-current="step"` only on the current item, and keeps every
stage title visible. Labels and statuses are target fixtures, not defaults.

## Usage Guidelines

<DoDont>
  <Do>Project all stages and their status from one authoritative checkout state.</Do>
  <Dont>Do not make steps links or buttons unless the target owns saved data, navigation availability, validation, routing, focus, errors, and announcements.</Dont>
</DoDont>

- Omit the complete component when its accessible name or ordered step content is absent.
- Keep stages in checkout order and expose at most one current item.
- Communicate the current stage in the host page title or primary heading as well as this supporting sequence.
- Provide completion text and a visible non-color cue.
- Use canonical Steps to customize stage presentation; P4 adds no duplicate token API.

## Accessibility

- Render the sequence as a non-empty labelled canonical ordered list.
- Apply `aria-current="step"` to at most one current item.
- Expose completed meaning through equivalent state text and a visible check or other non-color cue.
- Keep every title visible and in source order across horizontal, stacked, localized, RTL, zoomed, and forced-colors modes.
- P4 is passive and creates no focus stops or custom keyboard commands.
- Do not use `progressbar`, `tablist`, selected, checked, or `aria-orientation` semantics for the ordinary list.

## Target Translation

Neutral Web and Webflow compose the P4 wrapper with canonical Steps markup and
target-owned checkout state. React and Angular remain thin profiles over their
Steps adapter. Figma, SwiftUI, and Compose require equivalent ordered/current/
completed meaning after target review.

Shopify theme Liquid does not own the native checkout surface. A future Shopify
mapping requires an approved Checkout UI Extension target and supported Shopify
components/data; P4 must not claim that copied neutral DOM/CSS controls the
information, shipping, or payment steps.
