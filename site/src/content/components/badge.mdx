## Overview

Passive status or metadata label with Info, Success, Warning, and Error presentation.

## Presentation

Badge has one compact size and four semantic variants. Info is the default `.badge` style and intentionally has no modifier class.

| Property | Value | Web mapping |
| --- | --- | --- |
| `variant` | `info` | `.badge` |
| `variant` | `success` | `.badge--success` |
| `variant` | `warning` | `.badge--warning` |
| `variant` | `error` | `.badge--error` |
| `announceChanges` | `true` | `role="status"` |

## Usage Guidelines

### Visual customization

Studio and Exhibit expose 17 public roles. Badge owns horizontal/vertical padding
(10/2px), text weight (600) and letter spacing (0.05em); the relative `em` unit
tracks the chosen text size. Shared tokens supply Caption size and line height,
UI family, radius, background and text mix inputs. Text mixes 10% of the active
feedback foreground with primary text, so that input is not the final text color.

The v1 uppercase treatment, centered wrapping and forced-color system outline
remain CSS rules. Badge gains no action, icon, count or live behavior by changing
tokens. Use its existing Announce changes property only for dynamic status.
Adopt matching generated CSS and tokens in each consumer-owned copy.

<DoDont>
  <Do>Use Badge for a short passive status or a compact piece of metadata.</Do>
  <Dont>Do not make Badge clickable; use Button, Link, or Tag when the interface requires an action.</Dont>
</DoDont>

<DoDont>
  <Do>Choose visible text that communicates the meaning without color.</Do>
  <Dont>Do not use `role="status"` for static labels that never change.</Dont>
</DoDont>

Info communicates neutral context, Success a positive state, Warning a caution, and Error an unavailable or failed state.

## Accessibility

<Callout type="info">
  Badge is passive by default. Its visible text is its accessible content, and it does not enter the tab order.
</Callout>

- Keep the complete meaning in visible text rather than relying on the color family.
- Use `role="status"` only when the content changes dynamically and should be announced.
- Do not add a redundant `aria-label` when visible text already provides the complete status.
- Keep labels concise. Exceptional long or localized content wraps rather than being silently truncated or creating page overflow.
- Create the `role="status"` container before changing its text so assistive technology can observe the update; do not move focus to Badge.
