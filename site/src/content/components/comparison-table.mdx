## Overview

Comparison Table frames one finite target-owned matrix using canonical Data Table. It can remain passive or expose controlled alternative selection through canonical Radio or Checkbox controls. The table stays native: ordinary cells are not grid widgets, selection controls live only in alternative headers, and optional CTA controls remain independent from selection.

## Presentation

`interaction="passive"` is the semantic default and omits selection controls; explicit target-composed links or buttons may still appear. `interaction="selectable"` adds controlled selection. `selectionMode="single"` uses one native named Radio group, while `multiple` uses independent native Checkboxes.

The optional highlighted column is only visual emphasis. A recommendation, savings claim, “best value” label, availability statement, or other commercial meaning must be complete target-owned text. Checking an alternative never activates its CTA, and activating a CTA never silently changes selection.

The optional title remains outside horizontal scrolling. Canonical Data Table owns the native table surface, caption, headers, cell presentation, separators, overflow wrapper, wrapper focus, and responsive scroll. Every target must declare finite matrix bounds; Neutral Web intentionally does not impose a two-offering cap.

## Guidelines

<DoDont>
  <Do>Use one native matrix with complete alternative labels, criterion labels, values, and explicit claims or actions.</Do>
  <Dont>Do not turn ordinary cells into a grid, infer recommendations from highlight, or combine selection and CTA activation.</Dont>
</DoDont>

- Use `scope` for simple row/column headers; use explicit `id`/`headers` associations for complex matrices.
- Keep a real caption, even when visually hidden, and use it as concise selection context.
- Use Radio for mutually exclusive choice and Checkbox for independent multiple choice.
- Treat `selectedId` and `selectedIds` as controlled target state; update them from the emitted next selection.
- Keep action destinations, button behavior, persistence, analytics, prices, units, localization, and claims in their owning target.
- Preserve every essential column; horizontal scrolling is preferable to hiding data or creating an unrelated card layout.
- Pair checks, crosses, abbreviations, prices, and quantities with meaningful text.

## Accessibility

- A title creates a named native section; without a title, use a generic root.
- Keep the canonical table wrapper keyboard reachable and visibly focused, while the title stays outside its horizontal scroll.
- Native Radios share one non-empty name and support Tab, Space, and arrow-key movement. Native Checkboxes support independent Tab and Space activation.
- Give every choice a visible alternative label and contextual description through the table caption.
- Keep ordinary `th` and `td` cells passive and unfocusable; do not add `role="grid"`, roving tabindex, or directional cell navigation.
- Keep highlight, checked state, explicit claim text, and CTA activation as four separate meanings.
- Preserve source order, complete text, 200% text, user spacing, forced-color boundaries, and reduced-motion behavior.

## Specification

**Dependencies:** canonical Data Table, Radio, Checkbox, Link, and Button.

**Anatomy:** conditional `.comparison-table` root, `.comparison-table__inner`, optional title, required `.comparison-table__scroll.table-wrapper`, native `.comparison-table__table.table` with caption/headers/rows/cells, alternative headers, optional canonical choice controls, optional visual highlight and explicit claim text, text-complete status cells, and optional independent canonical actions.

## Shopify Translation

Owner decision 66 selects a variable but finite metaobject-backed matrix for Shopify. A dedicated adapter will reference one matrix record plus ordered alternative, criterion, and cell records. It must declare numeric alternative/criterion/cell limits, validate stable ids and complete rectangular relationships, preserve localized display strings, and define selection persistence and CTA behavior before becoming target-ready.

Custom or app-owned metaobject definitions cannot be used by a Theme Store-listed theme setting. The adapter must therefore distinguish custom storefront/app delivery from the Theme Store-safe profile rather than claiming one implementation covers both. Neutral Web keeps no Shopify schema or fixed two-offering limit.
