## Overview

Policy Page presents one complete passive legal document with a required visible title and semantic body. Optional update metadata keeps its visible localized text independent from an exact machine value, and an optional named table of contents composes canonical Links to target-owned section identifiers. The target supplies and publishes the legal content; the component does not define a CMS, revision model, localization pipeline, policy inventory, source API, or consent workflow.

## Presentation

The contextual article, header, visible title, and semantic body are required. Missing title or body omits the complete component. A target-formatted visible update label, its independent exact machine-readable value, and a table of contents are optional.

The table of contents renders only when it has a non-empty visible title and ordered items. Its anchors compose canonical Link and must resolve to unique target sections in the same order. The body preserves target-supplied headings, paragraphs, lists, links, tables, media, dates, quotations, code, and stable identifiers. The artwork is a fixture and does not establish a policy type, required clause, revision, effective date, or content source.

## Usage Guidelines

<DoDont>
  <Do>Preserve the legal document's semantic structure and source order.</Do>
  <Dont>Do not manufacture revision dates, index relationships, legal clauses, or a shared policy inventory.</Dont>
</DoDont>

- Keep table-of-contents links in the same order as their target sections.
- Omit an incomplete table of contents instead of leaving an unnamed navigation landmark.
- Use stable, unique in-page identifiers when a table of contents is supplied.
- Supply visible update text and exact machine-readable values independently; never parse the localized label.
- Use the explicit named overflow wrapper only when genuinely two-dimensional tables or code cannot reflow.

## Accessibility

- Keep one document-level `main`; P3 is a labelled article inside it, with a contextual title and non-skipping body hierarchy.
- Render exact update metadata as `<time datetime>` only when visible text and a valid machine value are both supplied.
- Place the optional table of contents in a labelled navigation landmark.
- Keep every descriptive table-of-contents Link paired with a unique section identifier in the same document.
- Preserve semantic lists, tables, links, quotations, media alternatives, and other structures from the target source.
- Keep long text, media, tables, and code contained at narrow widths without removing keyboard access to overflow.
- Add no custom policy role, menu keyboard model, active-section announcement, focus relocation, authored motion, or neutral runtime.
