## Overview

Checkout Progress is an informational ordered sequence of target-supplied complete, current, and upcoming steps. It exposes an accessible sequence label but does not own routing, navigation availability, visited state, validation gates, or synchronization with checkout state.

## Presentation

The ordered-list root, repeated steps, visible indicators, and visible labels are required. A generated decorative connector appears between adjacent steps. Upcoming steps use the default presentation, while `data-status="complete"` and `data-status="current"` select the two explicit status presentations.

The artwork keeps completion visible in text as well as color and places `aria-current="step"` only on the current step. Step labels and statuses are fixtures supplied by the target, not component defaults.

## Usage Guidelines

<DoDont>
  <Do>Supply complete, current, and upcoming statuses from one authoritative checkout state.</Do>
  <Dont>Do not make steps links or buttons unless a target separately owns the full navigation contract.</Dont>
</DoDont>

- Keep steps in checkout order and expose exactly one current step when the sequence has a current location.
- Provide a visible word or meaningful symbol for completion instead of relying on color.
- Keep every label visible when the layout stacks at narrow widths.
- Leave route transitions, visited state, availability, and validation gates to the target.

## Accessibility

- Render the component as an ordered list with an accessible sequence label.
- Apply `aria-current="step"` only to the current step.
- Expose complete status through visible text or a meaningful symbol in addition to color.
- Keep labels visible and in source order across horizontal and stacked layouts.
- Treat generated connectors as decorative and exclude them from the accessibility tree.
- Do not add link or button semantics unless a target explicitly supplies checkout navigation behavior.
