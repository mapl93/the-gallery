## Overview

Trust Badges presents a passive native list of short, text-complete commercial assurances supplied and governed by the target. Each item requires visible wording; an optional visual can reinforce that wording but remains decorative.

## Usage Guidelines

<DoDont>
  <Do>Use short, accurate, qualified statements whose evidence and current applicability the target can establish.</Do>
  <Dont>Do not use icon-only items, status or live semantics, unverified guarantees, hidden qualifications, or this component for payment brands.</Dont>
</DoDont>

Use Trust Badges for a compact wrapping row of independent one-string assurances. Use Badge for one status or metadata label, Shipping Info for a section-scale service or policy item with optional supporting text, and Payment Icons for recognized payment method marks.

The target owns claim truth, evidence, qualification, localization, jurisdiction, publication, updates, and any related policy destination. The component never verifies a promise through its icon, color, wording, or placement.

## Accessibility

- Render one native `ul` containing native `li` items and preserve source order.
- Require a non-empty `.trust-badge__text` in every valid item and omit the complete root when none remain.
- Hide redundant `.trust-badge__icon` visuals with `aria-hidden="true"` or empty image alt text.
- Add an optional localized accessible list label only when surrounding visible context does not already name the assurances.
- Keep passive assurances out of the focus order and do not add widget roles, live regions, keyboard commands, motion, or component runtime.
- Allow localized, RTL, unbroken, and enlarged text to wrap without truncation or overlap.
