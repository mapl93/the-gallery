## Presentation

Review Form owns the native `<form>` root, optional field wrappers, wrapping actions, and optional target-owned status region. Star Input owns rating selection. Input, Textarea, File Upload, and Select keep their canonical labels, native values, messages, Default, Error, Success, Warning, hover, focus-visible, disabled, and component-specific behavior. Button keeps native submit, disabled, busy, loading-indicator, label, and focus semantics.

The preview deliberately composes several validation families. Those states belong to the child controls, not `.review-form`. Its required rating, topic options, image-only file hint, and validation copy are documentation-fixture choices, not defaults or a review policy.

## Usage Guidelines

<DoDont>
  <Do>Compose the canonical controls and let each one own its field border, feedback, native attributes, and interaction states.</Do>
  <Dont>Do not recreate field validation, upload policy, select options, submit visuals, or response workflow with Review Form classes.</Dont>
</DoDont>

Required fields, option inventories, file types, counts, sizes, endpoint, authentication, consent, client and server validation, pending state, retries, duplicate prevention, moderation notice, success, error, reset, and post-submit focus all remain open target decisions.

Static Web may use native initial values and one native submit event. Framework adapters may control one live value per child or use child defaults, but must not keep a second Review Form copy of child state. A target starts Button busy state and response feedback only after a real submission workflow begins.

## Accessibility

<Callout type="info">
  The native form emits a submit request after browser and composed-control validation; transport and response behavior are target-owned.
</Callout>

- Preserve every composed control's native label, name, value, validation, reset, and submission behavior.
- Associate Input, Textarea, File Upload, Select, and Star Input messages with `aria-describedby`.
- Use `aria-invalid="true"` for Error only; Success and Warning keep descriptive messages without invalid state.
- Keep Default, Error, Success, and Warning distinguishable without relying on color alone, including hover and focused states.
- Keep File Upload's native input as the primary path and provide the actual accepted type, count, and size policy when the target defines it.
- Use a native submit Button. Busy state preserves its accessible name, uses `aria-busy="true"`, and prevents duplicate activation.
- Add live-region or focus movement behavior only as part of a separately defined target submission workflow.
