## Presentation

`products` is one required slot containing repeated Product Card compositions. Product identity, imagery, price, destinations, order, and per-product saved state are fixture or target data rather than top-level Wishlist properties.

The artwork includes the current `.wishlist-btn` hook inside each product fixture. The Wishlist contract does not expose that button as an independent property, so its ownership is not expanded here. `count` is optional and remains target-formatted.

## Usage Guidelines

<DoDont>
  <Do>Keep saved state, visible products, and count synchronized from one target-owned source.</Do>
  <Dont>Do not treat Product Card fixture data as Wishlist-level API.</Dont>
</DoDont>

- Let Product Card own product identity, media, price, and navigation.
- Preserve the customer's saved order when the target supports it.
- Reconcile optimistic add or remove actions with target persistence and failure feedback.
- Provide an intentional empty state when the products slot contains no saved items.

## Accessibility

- Give every saved-state toggle a product-specific accessible name.
- Keep `aria-pressed` synchronized with the actual saved state.
- Make count changes understandable after add or remove actions, using target-owned live feedback when needed.
- Preserve Product Card image alternatives, links, and heading hierarchy.
- Protect customer-specific saved items according to the target account or local-storage model.
