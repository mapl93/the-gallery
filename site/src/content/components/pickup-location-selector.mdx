## Overview

Pickup Location Selector finds eligible pickup locations for the exact current product, variant, and market, then records one stable location id as pickup intent. It does not reserve inventory or promise fulfilment; Product Form, Cart, or Checkout owns final confirmation and stale-selection recovery.

## Presentation

The required workflow is list-first: a canonical Input and Button submit manual search, an optional explicit Button requests location, and a native Fieldset of canonical Radios exposes eligible results. The quiet bordered records emphasize readable identity, address, availability, readiness, hours, and distance. A target may add a synchronized map, but the list remains complete when maps are unavailable or fail.

The surface responds to its own container. Below the private threshold, the search action stacks to full width; location content wraps through logical properties without hiding actions or requiring horizontal scrolling.

## Usage Guidelines

<DoDont>
  <Do>Bind selection to the exact current product, variant, and market, and emit the selected stable location id to the shared product or fulfilment coordinator.</Do>
  <Dont>Do not call selection a reservation, infer eligibility from quantity, request geolocation on mount, or make a map the only way to choose.</Dont>
</DoDont>

- Manual search by supported address, city, region, or postal code remains available under permission denial, timeout, browser incompatibility, or map failure.
- The target owns provider truth, geocoding, ordering, loading, empty/error/retry, stale suppression, localization, privacy, analytics, and transaction reconciliation.
- Supply eligible records only. When context changes, remove stale choices atomically before publishing the new result set.
- Use Store Locator for general branch discovery that does not choose a transactional pickup location.

## Accessibility

- Name the surface with a visible heading and the native search field with its own visible label; a placeholder is only a hint.
- Group location choices with a native Fieldset and first Legend. Each canonical Radio uses one shared name and the stable location id as its value.
- Associate every Radio with text-complete name, address, availability, and relevant readiness details; color, border, pins, and maps are supplemental.
- Preserve native Tab, Space, arrows, checkedness, focus, FormData, and reset behavior. Controlled targets own one `selectedLocationId`, not independent item booleans.
- Use one coherent `role=status` result channel and `role=alert` only for a newly presented error. Do not announce ordinary typing or map movement redundantly.
- Geolocation requires an explicit user action and target privacy disclosure. Selection must not announce inventory reservation or fulfilment confirmation.
