## Overview

Inline feedback message with semantic severity, optional icon, and optional dismiss action.

## Presentation

Info, Success, Warning, and Error are variants rather than interaction states. Title, icon, and dismissal are optional; message is required. Title uses the stable body scale and message uses the existing body-small size and line-height tokens.

| Variant | Web mapping |
| --- | --- |
| Info | `.alert--info` |
| Success | `.alert--success` |
| Warning | `.alert--warning` |
| Error | `.alert--error` |

## Usage Guidelines

<DoDont><Do>Use visible copy that explains the feedback and next step.</Do><Dont>Do not rely on color, icon, or live-region priority as the message.</Dont></DoDont>

Static alerts use no live-region semantics. Use Polite for non-urgent dynamically inserted feedback and Assertive only for urgent failures requiring immediate attention.

Long localized or indivisible title/message content wraps inside the alert. Semantic background tints use the feedback token directly; border and decorative icon use a stronger private, theme-aware derivation from the same family so their available-state contrast remains robust without adding a public token.

## Accessibility

- `announcement="none"` is the default for content already present on load.
- Polite maps to `role="status"`; Assertive maps to `role="alert"`.
- The visual term Banner never maps to the ARIA `banner` landmark.
- Hide decorative icons from assistive technology.
- Compose [Close Button](/components/close-button) for dismissal. When it is present, provide `dismissLabel`; let the consumer own removal, focus, persistence, and announcements.
