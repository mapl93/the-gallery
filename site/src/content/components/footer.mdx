## Presentation

`.footer__grid` responds to the Footer container rather than the document viewport: it stays one column when constrained and moves to the canonical brand-plus-three-group layout from 48rem. Each `.footer__group` is a `nav` named by its visible `.footer__heading`; `.footer__brand` and `.footer__bottom` remain ordinary content.

Footer owns semantic typography, wrap-safe touch targets, contrast-safe link states, and container composition. CMS schemas, newsletter behavior, locale selection, legal revisions, consent, social destinations, and external services remain target responsibilities.

## Usage Guidelines

<DoDont>
  <Do>Group destinations under clear headings and keep legal or locale metadata separate from navigation.</Do>
  <Dont>Do not make Footer the only route to critical support or account actions.</Dont>
</DoDont>

- Order groups by user need rather than by internal organization.
- Omit empty groups instead of rendering placeholder columns.
- Keep target-managed legal text current and readable; only render metadata as links when it has a real destination.

## Accessibility

- Use one body-scoped native `footer`; do not add a redundant `role="contentinfo"`.
- Use visible headings with `aria-labelledby` for each navigation group.
- Keep heading levels appropriate to the surrounding page hierarchy.
- Use native lists and descriptive links; preserve touch sizing, visible keyboard focus, reduced motion, and forced colors.
- Ensure long localized metadata remains readable at narrow container widths and does not rely on visual position for meaning.
