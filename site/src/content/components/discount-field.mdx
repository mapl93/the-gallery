## Overview

Discount Field is a native discount-code disclosure that composes the canonical Input and Button. It owns entry and confirmed-code presentation while the commerce target owns validation, applicability, requests, totals, and user feedback.

## Presentation

The root is a native `details` element and `toggleLabel` supplies its required `summary`. In static Web output, `expanded` selects the initial open state; stateful adapters may control the live open state and synchronize native toggle events.

The required `input` slot is the complete canonical Input composition. `applyLabel`, `applyDisabled`, and `applyBusy` configure the canonical submit Button without exposing request details. The optional `appliedCodes` slot is a native list of target-confirmed records; each record keeps the complete code in a `bdi` element and provides its own contextual removal Button.

## Usage Guidelines

<DoDont>
  <Do>Render a code in `appliedCodes` only after the commerce target confirms it.</Do>
  <Dont>Do not infer applicability, normalize the code, or recalculate totals inside Discount Field.</Dont>
</DoDont>

- Preserve the entered value when a recoverable validation response is shown.
- Project rejected or inapplicable candidates through the Input dependency's validation state.
- Keep application and removal pending states on their individual canonical Buttons.
- Place target-owned result status close to the component, without duplicating a live region inside it.
- Treat the code list as controlled target data; removal requests do not imply success until the target responds.

## Accessibility

- Use native `details` and `summary`; do not add redundant disclosure roles or manually duplicate `aria-expanded`.
- Give the discount input a visible label. Placeholder text is not its accessible name.
- Submit through a native form so Enter works from the input.
- Include the complete code in every removal Button's accessible name.
- Preserve visible focus for the summary and all canonical Button controls.
- Announce apply, rejection, removal, and total changes from the target-owned commerce status region.
