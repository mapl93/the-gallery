## Overview

A passive notification item with four feedback variants. Toast owns one item; target services own viewport placement, queues, timing, pause/resume, and removal.

## Usage Guidelines

<DoDont>
  <Do>Use toasts for short feedback after an action, such as saved changes or failed submissions.</Do>
  <Dont>Don't use toasts for blocking decisions or long content. Use a modal or inline message instead.</Dont>
</DoDont>

## Accessibility

<Callout type="warning">
  Toasts should announce important changes without stealing focus from the user's current task.
</Callout>

- Put live-region semantics on `.toast__content`, not on the root that also contains actions.
- Use `role="alert"` or `aria-live="assertive"` only for genuinely urgent changes; an Error visual does not imply assertive priority.
- Use `role="status"` or `aria-live="polite"` for routine confirmations.
- Do not auto-dismiss a toast while focus is inside it.
