## Presentation

Timeline has one vertical presentation. Markers and connectors are generated from each item; the final connector is omitted automatically. `status` supports `default`, `current`, `completed`, `delayed`, `warning`, and `error` on each entry.

`current` uses the system primary color and applies `aria-current="step"`. `completed` uses success, `warning` and the outlined `delayed` treatment use warning tokens, and `error` uses error tokens. The legacy `.timeline__item--active` selector remains a compatibility alias for current presentation.

Dates use the semantic secondary text color rather than a disabled-control color. Status text uses a contrast-strengthened mix of the existing feedback color and primary text; markers retain the semantic feedback colors. Forced-colors mode preserves filled versus outlined marker structure while visible status text remains the authoritative cue.

Dates, localized status labels, titles, descriptions, and the selected entry in Studio are fixtures. The target owns the repeated timeline data, chooses the title element appropriate to the surrounding heading hierarchy, and decides whether the sequence represents current progress.

## Usage Guidelines

<DoDont>
  <Do>Use Timeline for chronological or sequential events whose order carries meaning.</Do>
  <Dont>Don't mark an entry as current when the timeline is only a historical record.</Dont>
</DoDont>

Keep entry titles concise and use the content area for supporting detail. Long, localized, or unbroken content wraps within the component. Logical inline geometry mirrors the marker rail in RTL. Use Steps instead when users are completing a bounded multi-step task.

Use `delayed` for schedule variance, `warning` when attention is required, and `error` only when an entry has failed or contains an error. Do not use multiple statuses on one entry.

## Accessibility

<Callout type="info">
  Semantic presentation supplements ordered content; marker color is never the only source of meaning.
</Callout>

- Use `<ol>` and `<li>` when chronology or sequence is meaningful.
- Apply `aria-current="step"` only to the single current entry when the timeline represents progress.
- Add localized visible status text with `.timeline__status` when the state meaning matters.
- Keep dates, titles, and descriptions in a logical reading order.
- Do not use a disabled-control color for readable metadata or depend on marker color alone.

## Visual Customization

Twenty-seven public roles expose marker diameter/border/ring, top offset, marker-to-content gap, entry gap, connector width/start gap, metadata spacing and shared title/status weight. Existing semantic colors remain inputs to the six statuses: feedback status text is a 55% feedback / 45% primary mix. The surface-primary token colors the marker border, not its center.

The text inset derives from marker size + outer ring + content gap (10 + 2 + 32 = 44px initially). This replaces the old 24px root inset plus 20px entry inset without moving the visible content. Connector centering derives from marker/line widths; its start follows marker offset + size + ring + start gap. The connector still ends at the next entry boundary and the final connector is absent. These private geometric relationships are not additional public tokens.

Choose border/ring/marker dimensions coherently, leave room for readable content, and preserve visible status text. Resizing a marker does not change the current entry or its semantic meaning. The current border-box marker size assumes the canonical reset; copied consumers should adopt the full generated CSS/token slice together.

Consumers using copy-and-own must adopt updated CSS/tokens explicitly. Existing copies are not migrated automatically.
