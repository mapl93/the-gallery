## Overview

Password Reset presents a public reset-request surface with an optional passive icon, required title and guidance, a target-owned request form, and optional success feedback.

## Presentation

The primary artwork shows the request form. `form` composes Input and Button while preserving their native field, validation, and submit semantics. `icon` is passive and optional.

`successMessage` maps to `.password-reset__success` when the target renders confirmation feedback. The contract does not define whether request and success content coexist, replace one another, or how the transition occurs; that behavior remains target-controlled.

## Usage Guidelines

<DoDont>
  <Do>Use neutral confirmation copy that applies whether or not the address belongs to an account.</Do>
  <Dont>Do not reveal account existence through different success or error messages.</Dont>
</DoDont>

- Keep the request form concise and ask only for the identifier required by the target.
- Let the target own request submission, rate limiting, loading, failure handling, and reset-link delivery.
- Render the optional success message only from confirmed target state.

## Accessibility

- Associate the email input with a visible label and use `autocomplete="email"`.
- Connect field errors to the input and announce them when submission fails.
- Render success feedback in `.password-reset__success` with `role="status"` when it appears.
- Keep success copy neutral enough to avoid disclosing whether an account exists.
- Preserve native form submission and keyboard focus behavior.
