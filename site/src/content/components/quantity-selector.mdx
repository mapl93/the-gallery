## Overview

Editable quantity field with one native number input as its value owner and progressively enhanced, explicitly named step actions.

## Presentation

Default, Error, Success, and Warning share the same control anatomy. Validation feedback is composed through a field wrapper and associated with the native input.

The validation modifiers are `.qty--error`, `.qty--success`, and `.qty--warning`. Semantic boundaries are contrast-reinforced without introducing component-specific public colors. Hover preserves the selected family; focus adds its matching outer ring.

## Usage Guidelines

<DoDont>
  <Do>Set native min, max, and step constraints from the target's inventory rules.</Do>
  <Dont>Don't keep the buttons active past a valid boundary.</Dont>
</DoDont>

<DoDont>
  <Do>Keep the number input editable when customers may type a known quantity directly.</Do>
  <Dont>Do not replace the native input with text plus two buttons or a hidden mirror value.</Dont>
</DoDont>

### Native step ownership

The neutral Web enhancer calls the input's native `stepDown()` and `stepUp()` methods. This preserves the browser's step base, decimal alignment, `min`, `max`, and validity rules instead of reimplementing them in JavaScript. An absent, invalid, or non-positive adapter value falls back to `step="1"`.

Step buttons dispatch `input` and `change` only when the native value actually changes. Arrow Up and Arrow Down continue to work directly on the number input. Inventory availability, asynchronous cart updates, pending treatment, and recovery remain target-owned.

### State ownership

Static HTML uses `value` as the initial quantity and lets the native input own subsequent edits. Framework adapters may use `value` for controlled operation or `defaultValue` for uncontrolled operation, always on the same input.

`readOnly` keeps the input focusable and submittable while disabling both step actions. `disabled` removes the field from interaction and successful form submission. Form reset restores the initial value and the enhancer recalculates button availability.

## Accessibility

<Callout type="info">
  Quantity Selector owns structure, validation treatment, and neutral-web stepping. Inventory and cart persistence remain target-owned.
</Callout>

- Provide a visible label or equivalent accessible name.
- Name increment and decrement buttons clearly.
- Respect min, max, step, disabled, and inventory constraints.
- Add `name` when the value participates in form submission and `required` when an empty quantity must fail native validation.
- Associate validation feedback with `aria-describedby`; only Error sets `aria-invalid="true"`.
- Preserve native Arrow Up and Arrow Down behavior on the number field.
- Do not add `role="spinbutton"`; `input[type="number"]` already exposes the native numeric role and value semantics.
