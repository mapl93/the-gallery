## Overview

Controlled rich-media product collection for images, hosted video, external video, and models. One stable media id is current; selection stays manual and image detail delegates to canonical Lightbox.

## Presentation

The neutral item collection discriminates `image`, `video`, `external-video`, and `model`. Each record owns a stable id, localized label, preview, type-native data, and item-specific accessible text. AR is an adapter capability/action on eligible models, not another media type.

The product coordinator owns the collection, `currentId`, change handling, and variant synchronization. Framework targets may also offer `initialCurrentId`, but controlled and uncontrolled modes use the same state and never run a second DOM enhancer.

Selection only changes the current id. Video keeps a poster and explicit Play action; models keep a preview and explicit View in 3D action; eligible AR remains separate. Changing current media pauses and releases previous playback, provider iframe, or viewer content.

`imageDetail="lightbox"` is the full-product default. Activating a featured image opens canonical Lightbox over the image subset and synchronizes the same current id. `none` leaves images passive for already-modal surfaces such as Quick View. There is no second inline hover-zoom engine.

`loop` defaults to `false`. Finite navigation disables real collection bounds; loop wraps logical state without cloned records or duplicate controls. The collection never advances automatically.

## Usage Guidelines

Public tokens control the media ratio, compact/wide gaps, thumbnail size and
state opacities, rail bounds, badges, dots and focus. Thumbnail opacity roles
alias the existing opacity scale. The wide rail grows to fit an authored thumbnail
size; its minimum width is not an independent cap. The 48rem container switch
continues to change only the internal layout and relevant spacing.

Selection focus is inset so the native overflow rail does not clip it. The
current compact thumbnail and dot groups remain available; their product-level
visual density is a separate review decision. Native media controls, explicit
activation and Lightbox remain composed responsibilities, not copied token sets.

<DoDont>
  <Do>Provide complete discriminated records, stable ids, item-specific text, responsive image delivery, posters, explicit native activation, and one coordinator-owned current id.</Do>
  <Dont>Do not start playback on selection, fabricate an AR media type, load provider/model content before activation, or combine controlled state with the DOM enhancer.</Dont>
</DoDont>

Use canonical Button, Badge, Icon Button, and Lightbox dependencies. Thumbnail and compact groups remain ordinary named Button groups with `aria-current`; Product Gallery does not claim Tabs or Listbox semantics.

Shopify maps `product.media` to image, `video_tag`, `external_video_tag`, and `model_viewer_tag`. Interactive markup remains deferred in inert templates until explicit activation; eligible models may expose Shopify XR separately.

## Accessibility

- Keep hidden media, every selector group's `aria-current`, previous/next bounds, and the polite status synchronized to one stable id.
- Keep previous/next Buttons available because media controls can interfere with swipe; swipe is supplementary.
- Use item-specific `alt` for informative images and posters, `alt=""` for decorative previews inside named Buttons, and visible type Badges for non-image thumbnails.
- Do not autoplay the collection. Require explicit Play, View in 3D, and AR actions and retain native media controls.
- Lightbox owns modal naming, focus containment, Escape/backdrop/Close dismissal, restored focus, logical RTL navigation, direct swipe, and bounded zoom/pan.
- Respect reduced motion and forced colors; keep the 44px semantic compact target and visible focus treatment.
