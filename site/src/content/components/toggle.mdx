## Overview

Mutually exclusive pressed buttons for a compact view or mode selection.

## Presentation

The group has one size and one classless variant. Each slotted native button owns its label and `aria-pressed` value; `.toggle--active` mirrors the selected visual state.

| Property | Value | Web mapping |
| --- | --- | --- |
| `groupLabel` | string | `aria-label` on `.toggle-group` |
| `disabled` | boolean | native `disabled` on each `.toggle` |

## Usage Guidelines

<DoDont>
  <Do>Use Toggle for a small set of peer modes where one value remains selected.</Do>
  <Dont>Do not use it for unrelated commands or multiple independent filters.</Dont>
</DoDont>

The target owns option data, the initial value, and the effect of a selection. Neutral web progressively synchronizes one pressed item after activation; framework targets may control the value while updating every item atomically. Use Segmented Control when native radio semantics or form submission is required.

The group can shrink to its container. Localized or indivisible labels wrap instead of forcing horizontal page overflow, but labels should remain concise enough for compact mode selection.

The selected item uses the primary action surface and text tokens; it does not use the decorative statement color family.

## Accessibility

<Callout type="info">
  The base web pattern uses native buttons with `aria-pressed`; every option remains a normal keyboard focus stop.
</Callout>

- Label the group with `aria-label` or `aria-labelledby`.
- Keep exactly one `aria-pressed="true"` item for the registry-defined mutually exclusive pattern.
- Update visual selection and `aria-pressed` in the same state change.
- Preserve Enter and Space activation on each native button.
- Preserve normal Tab order; this pattern does not capture arrow keys or use roving focus.
- Use native `disabled` on every item when the entire mode choice is unavailable.
- Decorative surface, text, and border transitions are removed when reduced motion is requested.
