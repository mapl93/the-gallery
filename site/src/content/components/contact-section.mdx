## Overview

Contact Form arranges optional contact information beside a required native form composed from Input, Textarea, and Button. It does not duplicate field validation or submission behavior.

The parent owns only layout, introductory copy, details, and the form slot. Input and Textarea retain their labels, values, messages, validation families, disabled state, focus, hover, and native attributes; Button retains action state.

## Usage Guidelines

<DoDont>
  <Do>Compose complete field anatomy and keep the form focused on one clear contact purpose.</Do>
  <Dont>Do not recreate field variants, messages, or submit state as Contact Form properties.</Dont>
</DoDont>

Select is not a registered dependency of Contact Form. A target that supplies Select must preserve the Select contract rather than borrowing Input behavior.

## Accessibility

- Associate every field with a visible label and connect supporting messages with `aria-describedby`.
- Use `aria-invalid="true"` only for Error fields; preserve equivalent Default, Success, and Warning anatomy.
- Keep native form submission semantics and communicate busy, success, and error outcomes in the target implementation.
- Use native links for actionable contact details and preserve visible focus on all controls.
