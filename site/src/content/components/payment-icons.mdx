## Overview

Payment Icons presents a passive native list of recognized payment methods supplied by the current target. It owns list anatomy, semantic size and intrinsic wrapping; provider availability, official assets, names and brand rules remain target-owned.

The artwork uses neutral illustrative placeholders, not production logos or component defaults. Default marks are `1.5rem` high; Small uses `1.125rem`. Both preserve the target artwork and wrap from the component's own available inline space.

## Usage Guidelines

<DoDont>
  <Do>Render only methods confirmed by current target/provider data, using approved marks and a brief accessible method name for every item.</Do>
  <Dont>Do not bundle a static brand catalogue, advertise unavailable methods, or suppress official artwork with grayscale, opacity, hover-only reveal or recoloring.</Dont>
</DoDont>

Shopify should use the dedicated `payment-icons` snippet so `shop.enabled_payment_types` and `payment_type_svg_tag` remain the source of current types and official SVG output. Other targets supply equivalent current data and licensed assets.

## Accessibility

- Use native `ul`/`li` semantics; `role="list"` is only a marker-removal exposure safeguard.
- Name every informative image: non-empty `alt` for raster marks, or named image semantics for SVG and target-native marks.
- Omit invalid items and the complete root when no named recognized method remains.
- Add the optional localized list label only when surrounding visible context does not already identify the methods.
- Keep passive marks unfocusable and free of widget roles, keyboard behavior, live regions, hover disclosure and motion.
