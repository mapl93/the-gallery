## Overview

Determinate bar or circle that represents a known value, plus an indeterminate bar for unknown completion.

Bar and Circle are structural variants. Indeterminate is an orthogonal boolean state available only for Bar and omits `aria-valuenow`.

## Usage Guidelines

<DoDont><Do>Use determinate progress when the target can calculate a meaningful range.</Do><Dont>Do not show a fabricated percentage when completion is unknown.</Dont></DoDont>

Targets own calculations and localized value content. The component owns presentation and progressbar semantics.

Targets must keep `max` greater than `min` and clamp the current value into that range. Studio repairs an invalid edited range atomically so its preview never retains a stale fill. Enabling Indeterminate selects Bar; selecting Circle clears Indeterminate.

`displayValue` is optional, visible, and intentionally compact for either Bar or the token-sized Circle. `valueText` is independently optional and maps only to `aria-valuetext`, so it can carry a complete localized description. Neither falls back to, copies, truncates, scales, or derives from the other.

## Accessibility

- Provide a non-empty accessible operation label and meaningful finite min/max/value attributes. Invalid required composition emits no Progress root.
- Omit `aria-valuenow`, `aria-valuetext`, and visible value text while indeterminate; do not announce every small update.
- Use `aria-valuetext` when a localized phrase is clearer than the raw number.
- Neutral web removes transitions and indeterminate animation under reduced motion.

## Visual Customization

Studio and Exhibit expose 21 public roles. Bar track height, label gaps/preferred width and the moving segment use source tokens. The track is an inline-size container so indeterminate travel follows its own width when the segment width changes; it is not a new responsive mode. Duration/easing preserve 1500ms and the original CSS ease-in-out curve.

Circle diameter and visible ring width are independent pixel tokens. Defaults preserve 48px and the former visible 16/3px ring (4 SVG units at 48/36 scale). Current markup removes the scaled viewBox, derives the radius from diameter minus stroke and normalizes pathLength to 100. The legacy approximate radius grows by about 0.13px when fitted to the same 48px box; value percentages no longer depend on a circumference rounded to 100. At zero, the renderer hides the round-capped fill to avoid a dot suggesting progress.

Adopt the updated SVG markup together with CSS/tokens in copied consumers: centered percentage coordinates, no viewBox, and pathLength=100 on the circles. Old viewBox markup retains its authored radius and receives a non-scaling stroke, but does not gain radius fitting or percentage normalization until migrated. Keep stroke smaller than diameter and choose compact visible value text for the remaining interior; these tokens do not alter min/max/value or the accessible description.
