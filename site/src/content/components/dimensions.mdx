## Overview

Dimensions Display presents one required, target-formatted native measurement list with an optional explanatory visual and an optional canonical exclusive unit choice. The visible list remains authoritative; R5 does not measure, convert, round, localize, or infer values from media.

## Presentation

The required `measurements` slot supplies one or more complete native `dl` name/value groups. Every value is already formatted by the target and includes its unit and any qualification. R5 treats the value as text, isolates its direction, and never parses or converts it.

`visual` may contain target-owned image, SVG, diagram, and redundant annotations. Exact values must remain in the textual list. The shared specimen uses a truthful editorial image plus two assistive-hidden annotations; those are fixture/presentation details rather than public defaults or a product-media policy.

`unitControls` is optional. When present, it composes canonical Segmented Control: a visible legend, native same-name radios, exactly one selected value, and native keyboard/focus behavior. The target coordinates that selected value with a complete preformatted measurement and annotation set. R5 does not own a second selected-unit state or a conversion function.

### Behavior boundary

Dimensions owns no measurement algorithm, controlled/uncontrolled store, listener, observer, request, timer, persistence, URL state, form submission, live region, or announcement. A host can control or initialize the canonical radio group and replace the active slot content from its authoritative data source.

The current docs fixture holds independently authored `cm` and `in` strings so interaction can be exercised without implying a canonical numeric source, unit system, precision, or rounding rule.

### Responsive behavior

Canonical R5 responds to its own inline size. Visual and content stack by default; sufficiently wide hosts may use two regions. Measurement groups become one column in very narrow containers. Images, annotations, terms, formatted values, and canonical controls wrap or grow without a viewport or Studio-specific layout correction.

## Guidelines

<DoDont>
  <Do>Keep every quantity name, value, unit, qualifier, and tolerance in readable text even when a diagram repeats it.</Do>
  <Dont>Do not compute or imply conversion, precision, scale, or equivalence unless the target owns verified source values and rounding rules.</Dont>
</DoDont>

- Supply one coherent active formatted set; omit incomplete peers and omit R5 when no valid measurement remains.
- Keep the quantity name explicit. A unit symbol alone must not identify what was measured.
- Keep a separating space between a number and unit symbol where the target standard requires it.
- Use a diagram only when it clarifies where or how a quantity is measured.
- Give informative media a truthful alternative; hide only annotations that fully duplicate the visible list.
- Omit unit controls when the target provides one presentation or cannot guarantee equivalent sets.
- Use canonical Segmented Control for exclusive unit choice; do not recreate it with independent pressed buttons.
- Keep handmade variation, approximation, method, orientation, tolerance, and uncertainty visible when applicable.

## Accessibility

- Preserve native `dl > div > dt + dd` name/value relationships.
- Keep exact values in text, independent from image, line, position, scale, or color.
- Use `bdi` for target-formatted values and tabular numerals where comparison benefits from them.
- Do not truncate localized values, unit names, tolerances, or qualifiers.
- Name the optional unit choice with a visible legend and let native radio inputs own exclusivity, Arrow/Space behavior, focus, and checked state.
- Do not duplicate the selected unit as R5 state or make the complete list a live region by default.
- Preserve visual/list/control boundaries in forced colors and remove no focus indicator from the canonical control.

## Specification

**Dependencies:** canonical `segmented-control` for the optional interactive choice. R5 remains passive when that slot is absent.

**Anatomy:** generic `.dimensions` root; optional native `.dimensions__visual` and redundant annotations; required `.dimensions__content`; required native `.dimensions__table`; repeated `.dimensions__measurement > dt + dd > bdi.dimensions__value`; optional canonical `.segmented.dimensions__unit-control`.

### Targets

- **Neutral Web:** generic root, native description list, optional truthful figure, optional canonical radio-backed Segmented Control, intrinsic CSS, and zero R5 JavaScript.
- **Shopify:** planned until product/variant source, dimensions inventory, unit/precision/locale policy, merchant validation, and first consumer are approved.
- **Webflow / React / Angular:** targets provide complete formatted records and own any active-set coordination; do not move conversion into R5.
- **Figma / native targets:** model optional visual/control composition and narrow/wide modes; registered generic Figma nodes are not R5 visual approval.
