## Overview

Instagram Feed presents a finite collection of target-supplied studio or social media beneath optional account context. Authorization, fetching, caching, consent, freshness, moderation, failures, metrics, and provider integration remain target-owned.

The component is a passive presentation shell for already-rendered records. Its native unordered list preserves source order; each record uses a figure and optional visible caption. A target may wrap a figure in a native link only when a real destination exists. Passive items never receive a tab stop.

## Usage Guidelines

<DoDont>
  <Do>Supply a finite local or cached record collection, useful image alternatives, visible captions, and explicit real destinations.</Do>
  <Dont>Do not add `role="feed"`, artificial social metrics, fake anchors, generic focusable items, or content disclosed only on hover.</Dont>
</DoDont>

Keep account context accurate and avoid making essential content available only through an external feed.

## Accessibility

- Use a native `section` only when a visible heading can name it through `aria-labelledby`; otherwise use a generic `div`.
- Give informative media useful alternative text, explicitly decorative media `alt=""`, and keep captions visible without hover, focus, touch, color, or motion.
- Render the account handle only when both its label and real destination exist; never synthesize `#` or preview-only fallbacks.
- Keep passive items out of the tab order. Native handle, item, and action links retain accessible names, history, activation, full pointer targets, and visible focus.
- Omit the complete component when no valid items exist. Communicate loading, empty, stale, consent, and error conditions through the target data layer.
