## Overview

Size Chart is an on-demand product reference composed from canonical Modal, Data Table, and optional Segmented Control. It presents one complete target-authored measurement matrix without defining a universal product schema or conversion service. Web preserves this centered Modal at every viewport.

## Presentation

The root is a thin product profile. Its closed state contains a canonical link-style Button. Its open state contains the canonical Modal title, Close Button, scrollable body, optional unit choice, required Data Table, and optional notes.

The target supplies the complete table: caption, column and row headers, values, units, qualifiers, and source order. The first column should use row headers when it names each size. Keep the table static; do not add grid roles or keyboard navigation to passive values.

Unit choice is optional. When present, it is one canonical Segmented Control with a visible legend, same-name native radios, and exactly one checked value. A target replaces the complete authored chart for the selected option. Size Chart does not derive inches from centimetres, round values, select locale, or own a second `activeUnit` state.

The Web contract uses the canonical centered Modal at every viewport; it does not silently become a Sheet on narrow containers. A Sheet, full-screen surface, or inline chart is a different target composition rather than a D7 variant.

Shopify uses the merchant-owned `custom.size_chart` product metafield. Its referenced record supplies one required primary table and at most one optional secondary table, each independently authored and localized. The target adapter bounds each table to one row-header column, two measurement columns, and twenty valid rows. Larger or structurally different matrices require another target presentation instead of changing the neutral contract.

## Usage Guidelines

Notes paragraph gap is a public factor of Content spacing. Modal, Data Table,
Button and Segmented Control retain their own token APIs; Size Chart does not
duplicate those catalogues or expose a measurement conversion setting.

<DoDont>
  <Do>Provide concise headings, one complete measurement matrix, visible units, and any method or approximation note needed to interpret the values.</Do>
  <Dont>Do not force apparel, footwear, framed art, ceramics, furniture, or packaging into one fixed D7 row-and-column schema.</Dont>
</DoDont>

<DoDont>
  <Do>Supply separately verified complete tables when users can choose among unit presentations.</Do>
  <Dont>Do not treat fixture strings as a neutral conversion algorithm or infer precision, rounding, tolerance, or locale.</Dont>
</DoDont>

- Keep Size Chart secondary to the main product decision. If the matrix is the primary task or becomes very large, use a dedicated or inline presentation.
- Put each independent datum in its own cell and keep its row/column relationship explicit.
- Use notes for fit, measurement method, approximation, tolerance, or handmade variation only when the target can verify and localize that content.
- Keep selected variant, Size Chart content, Dimensions, preference persistence, and analytics coordinated by a target product service when those relationships are required.
- Do not expose modal width, overlay opacity, close placement, sticky headers, row hover, column count, breakpoint, conversion, or persistence as D7 public properties.

## Accessibility

<Callout type="warning">
  Modal CSS alone is not modality. The target must make outside content inert, move focus inside, contain Tab and Shift+Tab, close on Escape, and restore focus before asserting `aria-modal="true"`.
</Callout>

- Give the dialog a required visible title through `aria-labelledby` and a visible named Close Button.
- Initially focus the static title because the body contains a table and may contain multiple paragraphs. Omit `aria-describedby` by default so assistive technology users can explore the structure rather than hear one flattened announcement.
- Give the native table a meaningful caption and use `scope="col"` and `scope="row"` for simple header relationships.
- Keep the optional overflow wrapper keyboard focusable, contextually named, and visibly focused so narrow or enlarged content remains reachable.
- Use a visible Segmented Control legend and same-name native radios for optional unit choice. Native Tab, Arrow, and Space behavior belongs to that dependency.
- Keep visible units and qualifiers in the cells. Use `bdi` when independently formatted values can contain bidirectional text.
- Do not announce the complete table on every unit change. A target with evidence for additional feedback should provide one concise non-duplicative status.
- Preserve dark-mode contrast, forced-color boundaries, reduced motion, logical direction, long localization, user spacing, and effective 200 percent text.
