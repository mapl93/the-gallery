## Overview

Native collection of target-supplied review themes and optional counts. The
neutral component is passive; navigation or in-place selection remains an
explicit target decision.

## Presentation

The required `.review-highlights` root is a native unordered list. Each native
list item contains one `.review-highlights__tag` and may include a
target-formatted `.review-highlights__count`. The root can receive an accessible
name when surrounding content does not already identify the collection.

The shared Exhibit/Studio artwork uses passive text because no filtering or
navigation model has been accepted. The visual class can be projected onto
truthful native surfaces:

| Target intent | Native surface | State |
| --- | --- | --- |
| Passive classification | `span` | none |
| Navigation | `a[href]` | optional truthful `aria-current` |
| In-place selection | `button[type=button]` | projected `aria-pressed`; optional native `disabled` |

The component provides no transition. Passive and target-projected state
changes are immediate, so reduced-motion mode needs no special behavior.

## Usage Guidelines

<DoDont>
  <Do>Use the passive list until a target has explicitly chosen navigation or in-place selection behavior.</Do>
  <Dont>Do not infer filtering from pill styling or recreate selected appearance with a semanticless active class.</Dont>
</DoDont>

Theme extraction, counts, provider state, selection cardinality, URLs, result
updates, loading, focus, empty results and announcements remain target-owned.
Fixture values are evidence content, not component defaults.

For a filtering target, decide one of these contracts first:

- multi-select toggle buttons with a controlled or initial value array;
- single-select radio semantics with an explicit required-selection policy;
- navigation links with real destinations and history behavior;
- a separate Review Theme Filter component.

## Accessibility

<Callout type="info">
  Native element choice carries the interaction meaning; the pill surface never creates semantics by itself.
</Callout>

- Preserve the native `ul` / `li` relationship. `role="list"` keeps that
  relationship exposed when visual list markers are removed.
- Use plain text for passive themes, native links for navigation and native
  buttons for in-place selection.
- Put `aria-pressed` on a toggle button only after the target chooses that
  behavior, and keep its visible label stable.
- Use `aria-current` only for a truthful current navigation destination.
- Keep every count inside its theme item and provide a localized accessible unit
  or context; a bare number is ambiguous.
- Do not make the collection a live region. A target-owned results controller
  announces a complete localized message when necessary.

## State Ownership

The passive neutral component has no controlled/uncontrolled state and adds no
runtime. A target that projects buttons owns authored initial state, projected
state, activation requests, reconciliation, reset and persistence. A target
that projects links owns URLs, history, current destination, loading and focus.

## Target Translation

- **Web:** native list/list-item anatomy with passive `span`, native `a`, or
  native `button` surfaces.
- **Shopify:** a review-provider theme app block supplies taxonomy, localized
  counts and any URLs/actions while consuming generated Reviews CSS.
- **React / Angular:** passive list now; controlled/initial selection only after
  an interactive target contract is accepted.
- **Figma / native:** reproduce reviewed passive and target-mode visual states
  without inventing provider behavior.
