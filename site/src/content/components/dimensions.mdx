## Overview

Dimensions pairs required textual measurements with optional diagram content and target-owned unit controls.

## Presentation

The `measurements` slot is required. `visual` can contain a target-owned measurement diagram and textual annotations. `unitControls` is optional and preserves existing selected-unit visual hooks.

Targets own source values, formatting, conversion, rounding, control semantics, and synchronization. The artwork shows one coherent static state and does not supply conversion behavior.

## Guidelines

<DoDont>
  <Do>Keep every displayed measurement in readable text even when a diagram repeats it visually.</Do>
  <Dont>Do not perform or imply unit conversion in the component without target-owned values and rounding rules.</Dont>
</DoDont>

- Keep units adjacent to their values.
- Use a diagram only when it clarifies which dimension is being measured.
- Omit unit controls when the target provides only one formatted unit set.

## Accessibility

- Expose every measurement as text, even when a diagram is present.
- Give an informative diagram a useful text alternative.
- Use tabular numeric presentation where comparison benefits from it.
- If unit controls are provided, expose a coherent group name, selected state, and keyboard model.

## Specification

**Dependencies:** None.

**Anatomy:** `.dimensions`, optional visual and visual labels, required `.dimensions__table` term-value content, and optional `.dimensions__unit-toggle` controls.
