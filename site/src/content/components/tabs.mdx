## Overview

Tabs switches among related peer panels in one local context. The horizontal set
has one accessible name, one selected tab, roving focus, and one visible panel.

## Usage Guidelines

<DoDont>
  <Do>Use Tabs for related, preloaded content panels at the same hierarchy level.</Do>
  <Dont>Don't use Tabs for primary navigation, sequential steps, form choices, or unrelated destinations.</Dont>
</DoDont>

Use automatic activation only when a focused tab can reveal its preloaded panel
without noticeable latency. Use manual activation when selection requires Enter
or Space. Vertical, closable, reorderable, routed, lazy, and responsive Accordion
modes are outside the v1 contract.

## Accessibility

<Callout type="warning">
  Styling alone does not create Tabs. The target must coordinate selection,
  roving focus, ids, keyboard events, hidden panels, and one change event.
</Callout>

- Label the `tablist` and connect each `tab`/`tabpanel` pair with
  `aria-controls` and `aria-labelledby`.
- Keep exactly one enabled tab selected and one panel visible.
- ArrowLeft/ArrowRight wrap among enabled tabs; Home/End move to the first/last
  enabled tab. Manual mode waits for Enter, Space, or click to select.
- Include a text-only panel in the Tab sequence when it has no appropriate first
  focusable descendant.
- Skip disabled tabs and preserve visible focus independently from selection.
