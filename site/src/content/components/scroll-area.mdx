Single native overflow container with optional region naming, visible keyboard focus, progressive scrollbar styling, and no custom scroll runtime.

## Usage Guidelines

Thumb and track colors and focus width/inset are token-driven. Native scrollbar
thickness remains the browser's `thin` policy, switching to `auto` on coarse
pointers. It is not a pixel dimension. Track color starts transparent.

Studio groups thumb hover, radius and pixel thickness under **WebKit fallback
only**. These controls apply only where that non-standard styling path is used;
modern standards-based scrollbars ignore it and choose their own shape and
interaction rendering. Coarse fallback also returns to platform auto sizing.
The preview's height, padding and border frame belong to its sample content,
not to Scroll Area's native overflow contract.

<DoDont>
  <Do>Use Scroll Area when a bounded region must preserve one native scrolling surface.</Do>
  <Dont>Don't add a redundant landmark or focus stop when focusable descendants already make all overflow reachable.</Dont>
</DoDont>

## Accessibility

<Callout type="tip">
  Scrollbar styling is progressive enhancement. Native scroll behavior should remain intact.
</Callout>

- Add `role="region"`, `tabindex="0"`, and a label together only when keyboard users need to scroll the root directly.
- Keep content inside the scroll area reachable by keyboard.
- Do not replace native scrolling with custom drag-only mechanics.
- Preserve platform scrollbar colors in forced-colors and platform-sized affordances on coarse pointers.
