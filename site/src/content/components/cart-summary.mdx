## Overview

Cart Summary presents one target-owned cart snapshot and the primary checkout
handoff. It is a passive named section: the target supplies complete formatted
rows, checkout state, an optional expectation note, and optional provider-native
express checkout composition.

## Presentation

`rows` is a required semantic slot using one native description list. Every
target-authored row contains a localized `dt` label and complete `dd` value; at
least one `.cart-summary__row--total` is required. Use `bdi` around formatted
values so currency and mixed-direction text remain isolated.

The primary checkout action composes canonical Button. `checkoutDisabled`
represents target-owned unavailability and needs a visible explanation;
`checkoutBusy` composes Button's pending/disabled behavior without replacing the
label. Optional `express` content remains opaque provider-native composition.

Cart Summary is not sticky by itself. Cart Page or another target owns placement,
offset, scrolling and focus-obscuration behavior.

## Usage Guidelines

<DoDont>
  <Do>Derive every row and checkout state from one coherent commerce snapshot.</Do>
  <Dont>Do not calculate, relabel or announce monetary values inside presentation.</Dont>
</DoDont>

- Render only truthful subtotal, discount, shipping, tax, duty and total facts.
- Keep legal/estimate qualifications complete and concise in `note`.
- Do not use canonical Price for arbitrary summary facts such as Free or an
  estimated total.
- Keep provider actions inside the `express` slot and do not inspect their
  internal DOM, lifecycle or analytics.
- Keep Cart Drawer's compact summary isolated; it does not compose K3.

## Accessibility

- Name the section with a visible context-correct heading.
- Preserve native `dl`, `dt`, and `dd` relationships and label-then-value DOM order.
- Keep the primary checkout Button before optional express actions in focus order.
- Preserve checkout label while disabled or busy and provide a visible reason
  for unavailability.
- Announce cart or checkout results once through a parent target status with
  complete context; do not make totals or individual values live regions.
- Parent-owned sticky placement must not obscure focused content.
