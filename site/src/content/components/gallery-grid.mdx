## Overview

Gallery Grid arranges a finite ordered list of target-owned media beneath an optional contextual heading. It remains passive until a target supplies legitimate native interaction.

`grid` is the default regular row-major presentation and uses a private uniform crop. `masonry` maps to `.gallery-grid--masonry`, follows source flow through CSS columns, and preserves natural media proportions. Both respond to component space rather than the page viewport.

A titled composition is a native section named by its visible heading. Without a title, use a generic root. The required `items` slot uses a native list and invalid empty composition is omitted.

## Usage Guidelines

<DoDont>
  <Do>Choose media with a coherent visual relationship and supply explicit native semantics when an item has a destination.</Do>
  <Dont>Do not assume gallery items open a lightbox, navigate, or trigger commerce behavior.</Dont>
</DoDont>

Let each target decide whether an item remains passive media or contains a native link/button after activation is established. Passive items are not focusable and do not zoom on hover.

Masonry Gallery remains a separate storytelling contract with caption anatomy. Whether Gallery Grid should retain its image-only masonry presentation is an explicit human architecture review question; do not alias the components silently.

## Accessibility

- Provide useful alternative text for informative images and empty alternatives for decorative images.
- Use native links or buttons only when an item has established navigation or command behavior.
- Keep captions and essential information available without hover.
- Preserve visible focus for any target-supplied interactive descendants.
- Keep DOM/source order authoritative and do not use APG grid roles, dense packing, or visual reordering.
