## Overview

Native password entry with one value owner, a synchronized visibility action, and optional text-backed strength feedback for new passwords.

## Presentation

Password Input keeps validation, visibility, strength, disabled, readonly, and required as independent concerns. Its CSS surface follows the accepted Input semantics without consuming Input's private variables.

## Usage Guidelines

<DoDont>
  <Do>Use purposeful autocomplete, allow password managers and paste, and keep the same native input mounted when revealing its value.</Do>
  <Dont>Don't show strength for a current-password field or use bars without equivalent localized text.</Dont>
</DoDont>

## Accessibility

- Associate the native password field with a visible label and optional guidance or validation ids.
- Keep toggle name, `aria-pressed`, `aria-controls`, icon, and input type synchronized.
- Use `type="button"` so visibility never submits the form.
- Prefer `current-password` for sign-in and `new-password` for password creation or change.
- Readonly values remain focusable and submittable; disabled values are unavailable and omitted from form data.
- Strength is not a live region by default. The target owns scoring and announcement timing.
