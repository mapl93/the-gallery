## Overview

Category Nav is a horizontally scrollable region for target-owned blog categories, optional counts, and current-state markup. The target chooses whether its items are destinations or in-place controls.

The component has one default presentation. Items use `.category-nav__item`, counts use `.category-nav__count`, and a target-supplied current link may use `.category-nav__item--active` with `aria-current="page"`.

## Usage Guidelines

<DoDont>
  <Do>Choose links for category pages or native controls for an in-place filtering model.</Do>
  <Dont>Do not mix page-current semantics with an in-place selection model.</Dont>
</DoDont>

Whether Category Nav navigates to category pages or filters the current result set remains unresolved. The layer responsible for synchronizing URLs, current state, and filtered results also remains unresolved. The preview demonstrates a link-based target fixture, not a canonical behavior decision.

## Accessibility

- Use a `nav` landmark with an accessible label that distinguishes blog categories from other navigation.
- Use `aria-current="page"` only for a link representing the current category page.
- For a filtering model, use native controls and selection semantics appropriate to the accepted behavior.
- Preserve horizontal keyboard access, visible focus, and touch-sized items.
- Keep overflowing items scrollable rather than clipping their labels.
