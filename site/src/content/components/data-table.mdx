## Presentation

The base table can independently compose striped rows, row hover, and sortable-header anatomy. These controls are intentionally not exclusive: a sortable table may also be striped and preserve hover feedback. The responsive wrapper is optional anatomy and does not change table semantics.

Rows, columns, values, and the sample inventory in Exhibit and Studio are fixtures, not component defaults. Sortable presentation supplies the canonical control anatomy; each target owns comparison, locale rules, ordering, pagination, and remote data updates.

## Usage Guidelines

<DoDont>
  <Do>Use Table when values need to be compared across consistent columns.</Do>
  <Dont>Don't use table markup only to align unrelated page content.</Dont>
</DoDont>

Keep column labels concise and preserve the same data meaning down each column. Use the overflow wrapper when the table may be wider than its container instead of compressing cell content until it becomes unreadable.

## Accessibility

<Callout type="info">
  Native table structure provides relationships that a collection of generic grid containers does not.
</Callout>

- Use `<thead>`, `<tbody>`, `<th>`, and `<td>` according to the data structure.
- Add `scope="col"` or `scope="row"` for simple headers and explicit header associations for complex tables.
- Place `aria-sort` on the currently sortable header cell and synchronize it with the visible row order.
- Keep sort triggers as native buttons; do not rely on pointer hover or icon direction alone.
