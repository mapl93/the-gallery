## Overview

Header is the global site masthead. It combines required brand content and destination with optional primary navigation, target-owned actions, cart count, and a Button-composed mobile-menu trigger.

## Presentation

The root owns the sticky horizontal composition and establishes an inline-size container. The optional primary navigation is hidden until the existing 48rem composition threshold fits inside Header itself, not merely inside the viewport. A consuming target may supply `mobileMenuTrigger` through `.header__hamburger` when it also provides the corresponding Mobile Menu or Drawer runtime.

Brand content, destinations, navigation records, actions, and cart state are target data. Header does not decide which global actions exist or connect them to Search Overlay, Cart Drawer, Mobile Menu, Drawer, or Mega Menu.

## Usage Guidelines

<DoDont>
  <Do>Keep the brand destination, primary navigation, and target-owned actions consistent across the site shell.</Do>
  <Dont>Do not duplicate overlay behavior or commerce state inside Header.</Dont>
</DoDont>

- Keep the visible action set focused at each breakpoint.
- Compose actions from canonical Button or native Link implementations and add `.header__action` only as the Header positioning hook.
- Supply `cartCount` only when a target can keep it synchronized with cart state.
- Use the Button dependency for an optional mobile-menu trigger without making its fixture content a Header default.

## Accessibility

- Give the optional primary navigation a useful accessible name.
- Mark the current destination with `aria-current="page"` when applicable.
- Ensure the brand link has an accessible name; use `logoLabel` only when visible brand content is insufficient.
- A target-connected mobile-menu trigger must synchronize `aria-expanded` and `aria-controls` with the controlled surface.
- Announce meaningful cart-count changes according to the target's live-region policy rather than relying on the badge alone.
- A top-level `<header>` already exposes the banner landmark; do not add a redundant `role="banner"`. Nested Header previews are not page banners.
- Sticky targets must preserve focused and fragment-linked content below the occupied header; scroll offset policy belongs to the page shell.
