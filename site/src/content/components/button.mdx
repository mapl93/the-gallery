## Overview

Button is the foundation for interactive actions in The Gallery. Its public contract supports five visual variants, three sizes, independent leading and trailing icon slots, disabled and busy states, icon-only layout, and full-width layout.

The control-coherence pilot aligns default Input and Button at 46 px across viewport modes, with 16 px text and 24 px line boxes. Button uses 10 px vertical padding plus its border; icons and loading fit within the text line. Long labels may grow rather than clip. Small and large Button are separate sizes. ## Presentation

Studio exposes border and focus dimensions, loading stroke/duration and Link
underline offset alongside the existing colors, radius, padding, icon and type
controls. Line height is a unitless multiplier: `1.5` means 24 px with 16 px text.
Small/large sizes retain their relative scaling; Link retains its intrinsic,
unpadded default layout. Customize those treatments deliberately when copying.

Primary is the default variant and default is the default size. Their absence of a modifier class is intentional.

| Property | Value | Web mapping |
| --- | --- | --- |
| `variant` | `primary` | `.btn` |
| `variant` | `secondary` | `.btn--secondary` |
| `variant` | `outline` | `.btn--outline` |
| `variant` | `link` | `.btn--link` |
| `variant` | `danger` | `.btn--danger` |
| `size` | `sm` | `.btn--sm` |
| `size` | `default` | `.btn` |
| `size` | `lg` | `.btn--lg` |

`iconOnly` maps to `.btn--icon-only`. `fullWidth` maps to `.btn--full`. Both are independent boolean properties rather than variants.

### Icon Composition

`leadingIcon` and `trailingIcon` are independent slots and may be used together. Every positioned icon composes the base `.btn__icon` class with its position class.

`--space-button-icon-edge-offset` reduces outer padding on each positioned-icon
side of a labeled button. Its 3.333333 px default compensates the visible outer
inset of the 20 px ArrowRight fixture: 20 px base padding becomes approximately
16.67 px beside the SVG box. Studio exposes **Icon edge offset**; set it to zero
to disable, or tune it when changing icons or icon size. This is optical tuning,
not automatic measurement of arbitrary artwork. SVG paths and viewBoxes stay intact.

Text-only, icon-only and Link buttons retain their existing padding. Both icons
receive the same correction on their respective logical sides, including RTL.
Loading preserves the replaced slot's outer size and button width by insetting
its circle within that slot. The correction is bounded by the available padding
and icon space, so extreme overrides cannot create negative padding or spinner sizes.

```html
<button class="btn" type="button">
  <svg class="btn__icon btn__icon--leading" aria-hidden="true"><!-- icon --></svg>
  <span>Add to cart</span>
  <svg class="btn__icon btn__icon--trailing" aria-hidden="true"><!-- icon --></svg>
</button>
```

An icon-only button uses the same slot classes and requires an accessible name.

```html
<button class="btn btn--outline btn--icon-only" type="button" aria-label="Search">
  <svg class="btn__icon btn__icon--leading" aria-hidden="true"><!-- icon --></svg>
</button>
```

### Disabled

Native buttons use the `disabled` attribute. Disabled anchors keep `role="link"` and `aria-disabled="true"` but omit `href` until they become available again.

```html
<button class="btn" type="button" disabled>Unavailable</button>

<a class="btn" role="link" aria-disabled="true">Unavailable destination</a>
```

### Loading

Set `aria-busy="true"` while an action is pending. A busy native button also uses `disabled`; a busy anchor keeps `role="link"` but omits `href`. Loading therefore blocks mouse, touch, and keyboard reactivation while keeping the visible label, accessible role, and accessible name in place.

- An explicit `data-loading-position="leading"` or `data-loading-position="trailing"` wins.
- Without an explicit position, one configured icon determines the loading side.
- Without icons, loading defaults to leading.
- With both icons, loading defaults to leading.
- The icon on the opposite side remains visible.

```html
<!-- One trailing icon: loading infers trailing and replaces that icon. -->
<button class="btn" type="button" aria-busy="true" disabled>
  <span>Continue</span>
  <svg class="btn__icon btn__icon--trailing" aria-hidden="true"><!-- icon --></svg>
</button>

<!-- Explicit trailing: the leading icon and label remain visible. -->
<button class="btn" type="button" aria-busy="true" data-loading-position="trailing" disabled>
  <svg class="btn__icon btn__icon--leading" aria-hidden="true"><!-- icon --></svg>
  <span>Save changes</span>
  <svg class="btn__icon btn__icon--trailing" aria-hidden="true"><!-- icon --></svg>
</button>

<!-- Busy navigation has no actionable href. -->
<a class="btn" role="link" aria-busy="true">Preparing destination</a>
```

## Usage Guidelines

<DoDont>
  <Do>Use one primary button per section to establish a clear action hierarchy.</Do>
  <Dont>Do not place multiple primary buttons side by side; demote one to secondary or outline.</Dont>
</DoDont>

<DoDont>
  <Do>Use the danger variant for destructive actions such as delete or remove.</Do>
  <Dont>Do not use danger for non-destructive actions.</Dont>
</DoDont>

## Accessibility

- Use `<button>` for actions and `<a>` for navigation.
- Keep the visible focus indication provided by `:focus-visible`.
- Use native `disabled` on buttons. A disabled anchor keeps `role="link"` and `aria-disabled="true"` but omits `href`.
- Keep the label unchanged while `aria-busy="true"` so the accessible name remains stable. Busy buttons also use `disabled`; busy anchors keep `role="link"` but omit `href`.
- Mark decorative icons as hidden from assistive technology when the visible label already names the action.
- Provide `aria-label` or equivalent accessible text for every icon-only button.
