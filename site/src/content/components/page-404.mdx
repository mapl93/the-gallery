## Overview

404 Page presents a missing-page message with optional illustration, search, recovery links, and suggested content. Search handling, routes, and suggested records remain owned by the consuming target.

## Presentation

The centered root contains a required page-level heading and explanatory message. The visible error code, illustration, native search form, recovery-link group, and suggested-content region are optional and independent.

Recovery destinations and copy in the artwork are preview fixtures. The component provides layout and focus presentation but does not define route availability, search submission, or suggestion data.

## Usage Guidelines

<DoDont>
  <Do>Explain that the page is unavailable and provide at least one target-owned recovery path.</Do>
  <Dont>Do not imply that search, routes, or suggested records are supplied by the component.</Dont>
</DoDont>

- Keep the message concise and distinguish it from a temporary loading or service-error state.
- Use the illustration only when it supports the message; it must not carry essential information alone.
- Preserve native link semantics for recovery destinations and native form semantics when search is supplied.

## Accessibility

- Use one page-level heading that clearly communicates the missing-page state.
- Place recovery destinations in a labelled navigation landmark when more than one is present.
- Give an optional search form an accessible name and preserve visible focus on its field and submit action.
- Provide useful alternative text for meaningful illustration media and hide purely decorative media from assistive technology.
- Keep recovery-link labels descriptive without relying on surrounding visual context.
