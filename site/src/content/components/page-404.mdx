## Overview

404 Page is a missing-resource composition with a required explanation and at
least one useful target-owned recovery path. It composes canonical Empty State,
Input, Button, and Link; the server or application still owns HTTP status,
caching, routing, search, suggested records, localization, and analytics.

## Presentation

The container-responsive root centers a canonical Empty State explanation,
optional visible code, optional recovery search, additional navigation, and an
optional native list of suggestions. A visually primary destination can sit in
the Empty State core; additional destinations remain ordinary canonical Links.

The illustration, copy, search query, routes, and suggested records in Exhibit
and Studio are fixtures, not defaults. The optional code is redundant visual
metadata and is hidden from accessibility because the required heading explains
the state in words.

## Usage Guidelines

<DoDont>
  <Do>Explain the absence clearly and provide at least one real, useful recovery path.</Do>
  <Dont>Do not turn P1 into an HTTP response, router, search service, recommendation engine, or generic service-error screen.</Dont>
</DoDont>

- Keep the heading and message non-empty; omit the complete composition when
  either is unavailable.
- Supply at least one of search, recovery destinations, or suggested
  destinations. Empty recovery shells are invalid.
- Use one clearly primary destination and keep additional choices restrained.
- Keep search action, query schema, results, errors, and analytics with the
  consuming target.
- Keep suggestion source, ranking, availability, and localization target-owned.

## Accessibility

- Place the composition inside the one document-level `main` owned by a
  standalone target. Inside another page, use a labelled contextual section.
- Use a visible contextual heading and preserve the host document hierarchy;
  P1 does not expose a universal heading-level property.
- Mark the optional illustration decorative and hide the redundant visible code
  from assistive technology.
- Compose search from a named native form, visible Input label, named
  `type="search"` field, associated message, and visible submit Button.
- Use descriptive real `href` values; do not cancel placeholder fragments.
- Render suggestions as a labelled native list and preserve target-authored
  order, canonical focus, forced-colors, reduced-motion, keyboard, and touch
  behavior.
