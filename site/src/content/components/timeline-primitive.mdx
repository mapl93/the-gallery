## Presentation

Timeline has one vertical presentation. Markers and connectors are generated from each item; the final connector is omitted automatically. `status` supports `default`, `current`, `completed`, `delayed`, `warning`, and `error` on each entry.

`current` uses the system primary color and applies `aria-current="step"`. `completed` uses success, `warning` and the outlined `delayed` treatment use warning tokens, and `error` uses error tokens. The legacy `.timeline__item--active` selector remains a compatibility alias for current presentation.

Dates, localized status labels, titles, descriptions, and the selected entry in Studio are fixtures. The target owns the repeated timeline data and decides whether the sequence represents current progress.

## Usage Guidelines

<DoDont>
  <Do>Use Timeline for chronological or sequential events whose order carries meaning.</Do>
  <Dont>Don't mark an entry as current when the timeline is only a historical record.</Dont>
</DoDont>

Keep entry titles concise and use the content area for supporting detail. Use Steps instead when users are completing a bounded multi-step task.

Use `delayed` for schedule variance, `warning` when attention is required, and `error` only when an entry has failed or contains an error. Do not use multiple statuses on one entry.

## Accessibility

<Callout type="info">
  Semantic presentation supplements ordered content; marker color is never the only source of meaning.
</Callout>

- Use `<ol>` and `<li>` when chronology or sequence is meaningful.
- Apply `aria-current="step"` only to the single current entry when the timeline represents progress.
- Add localized visible status text with `.timeline__status` when the state meaning matters.
- Keep dates, titles, and descriptions in a logical reading order.
