## Overview

Order History is an authenticated, labelled region containing a target-owned collection of order rows. Each row presents a destination, date, readable status, and formatted total.

## Presentation

`orders` is one required slot containing repeated order rows. Order number, date, status, total, destination, row count, and ordering are fixture or target data; they are not independent Order History properties.

The labels and status modifiers shown in the artwork demonstrate the current visual hooks only. The contract does not establish a canonical commerce status taxonomy. Each target maps its own order state to readable text and an appropriate Badge presentation.

## Usage Guidelines

<DoDont>
  <Do>Format dates, statuses, destinations, and totals from the same authoritative order record.</Do>
  <Dont>Do not infer order state from color or presentation-only class names.</Dont>
</DoDont>

- Sort and paginate the repeated rows according to target account behavior.
- Keep the order number as a direct link to the corresponding detail view.
- Use concise, customer-facing status copy derived from target data.
- Provide a distinct empty state outside the repeated row slot when no orders exist.

## Accessibility

- Protect order history behind the target authentication system.
- Use `label` to name the region when surrounding headings do not already do so.
- Keep order numbers as links with clear destination context.
- Expose every status as readable text and never through color alone.
- Use semantic dates and preserve a logical reading order at narrow widths.
