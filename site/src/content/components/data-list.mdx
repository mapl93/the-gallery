Semantic description list for concise key-value metadata that remains readable in narrow component containers.

## Presentation

`vertical` is the default and presents one bordered key-value row at a time. Below a `20rem` component container, each row stacks its term and value without changing source order. `horizontal` removes row rules and wraps each pair as a compact metadata group. The property changes layout only; it does not change description-list semantics or own the repeated content.

## Usage Guidelines

<DoDont>
  <Do>Use Data List for related terms and descriptions that users need to scan or compare.</Do>
  <Dont>Don't use it for tabular datasets with column relationships; use Data Table instead.</Dont>
</DoDont>

Keep terms concise. Prefer the vertical layout when descriptions are long or the available width is narrow. Long, localized, or unbroken values wrap within the component instead of expanding the page.

## Accessibility

<Callout type="info">
  Data List preserves native description-list semantics in both layouts.
</Callout>

- Use native `<dl>`, `<dt>`, and `<dd>` semantics when rendering descriptive metadata.
- Keep each term adjacent to its description in source order.
- Preserve logical start/end alignment in LTR and RTL content.
- Do not add list semantics that conflict with the native description list.

## Visual Customization

Twelve public roles expose inline pair gap, vertical row padding/border, horizontal group row/column gaps, stacked pair gap and shared medium value weight. The stacked gap applies both to horizontal metadata groups and to narrow vertical rows. Horizontal layout removes row separators and row padding; Studio hides those inapplicable controls.

The existing 20rem container query decides when vertical rows stack. Tokens supply the spacing values for each layout; they do not repeat the catalogue or add viewport modes. Inline pair gap applies while the pair is side by side, and stacked pair gap applies after stacking. Source order, logical alignment, wrapping and the absence of a last-row separator remain structural rules. Horizontal is a layout variant, not an interaction state.

Copied consumers must explicitly adopt updated source-derived CSS/tokens. These controls do not update existing copies automatically or certify arbitrary colors, sizes or target content.
