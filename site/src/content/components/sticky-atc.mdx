## Overview

Sticky Add-to-Cart Bar keeps current product identity, target-formatted Price, and one purchase submitter available when target logic decides the main Product Form is no longer the useful action surface. It submits that existing form rather than creating another form or cart path.

## Presentation

The source order stays product information, then purchase action. The inner composition responds to K9's own container: at constrained widths the action occupies a separate full-width row while title and Price remain available. Maximum width, threshold, image treatment, gaps, surface chrome, and movement are private implementation details pending human visual review.

`title`, `actionLabel`, and `productFormId` are required non-empty values. `image` and its target-authored `imageAlt` are optional. `price` is an optional canonical Price slot, not a raw money string. `visible`, `actionDisabled`, and `pending` project state from the target coordinator without creating K9-owned commerce state.

The root has no landmark, toolbar, dialog, or live-region role. On Web, a hidden K9 is both `inert` and `aria-hidden="true"`; translation alone is not sufficient. The target owns when the bar mounts, appears, hides, or completes an exit transition.

## Usage Guidelines

<DoDont>
  <Do>Associate the sticky canonical Button with the same native Product Form and synchronized product coordinator as the main action.</Do>
  <Dont>Do not create a second form, local cart request, inferred “Added” state, or duplicate purchase announcement.</Dont>
</DoDont>

- Keep selected merchandise, options, quantity, selling plan, Price, media, URL, inventory, availability, pending/result state, cart updates, and feedback synchronized through one target product coordinator.
- Expose K9 only after the main Product Form action is no longer usefully visible and coherent product eligibility exists. Each target documents its own observation signal, thresholds, and hysteresis; K9 does not implement them.
- Reserve dynamic block-end scroll space and coordinate safe areas, virtual keyboards, Bottom Nav, Cookie Consent, Cart Drawer, chat, and other fixed surfaces.
- Use `actionDisabled` for an unavailable resolved selection and provide a visible explanation in the surrounding product context. Use `pending` only while target purchase work is in progress.
- Do not expose fixed height, breakpoint, image size, shadow, border, gap, action width, observer threshold, z-index offset, or transition distance as public K9 properties.

## Accessibility

- On Web, use a real `button[type="submit"][form]` so the sticky action preserves Product Form constraint validation, activated-submitter semantics, named successful entries, and FormData.
- Keep hidden descendants inert and accessibility-hidden. Do not repair a visually translated subtree with only one descendant `tabIndex`.
- Preserve a visible localized product title and action label, canonical Price bidirectional isolation, and correct optional image alternative text. Empty image alt is appropriate only when the adjacent title communicates the same identity.
- Pending uses canonical Button `aria-busy="true"` plus disabled semantics, preserves the visible label, and prevents repeat submission.
- Keep target result status, focus, errors, retry, and announcement timing in one purchase/cart lifecycle; K9 itself is not a status region.
- Ensure the fixed surface never completely obscures keyboard focus or checkout-critical controls. Test effective 200 percent zoom, reflow, reduced motion, forced colors, logical direction, safe areas, and short viewports.
