## Overview

Tags Input is a labelled free-form multi-value field. It composes the canonical
Field Wrapper for label and feedback, canonical Tags for committed values, and
one native text input for draft editing. The target owns the controlled value
collection, validation, persistence, localization, and form serialization.

## Presentation

The field supports `default`, `error`, `success`, and `warning` validation
families. Committed values wrap inside the field boundary while the draft keeps
a useful editing width and moves to a new row when the container narrows.

## Usage Guidelines

<DoDont>
  <Do>Use Tags Input for short free-form values when the owning target can validate and persist the complete collection.</Do>
  <Dont>Don't use it as a multi-select or autocomplete without composing a complete Combobox popup and keyboard contract.</Dont>
</DoDont>

- Enter requests one trimmed non-empty value after text composition ends.
- Keep draft text distinct from committed values in controlled adapters.
- Use explicit named Tag remove buttons. The v1 field does not delete values on
  empty Backspace or turn commas, blur, or pasted text into implicit commits.
- Keep duplicate equivalence, allowed characters, limits, server identity,
  ordering, asynchronous validation, and persistence in the owning target.
- Read-only preserves readable/focusable content without remove actions.
  Disabled also disables the native field and every rendered remove action.

## Accessibility

<Callout type="tip">
  The free-form v1 field has no suggestion popup, so it remains a labelled native
  text input and does not expose Combobox, Listbox, `aria-autocomplete`,
  `aria-expanded`, or active-option semantics.
</Callout>

- Provide a visible explicit label; placeholder text is supplementary only.
- Associate persistent guidance and current feedback through
  `aria-describedby`. Error sets `aria-invalid="true"`; Success and Warning do
  not.
- Communicate a required collection with `aria-required` and target validation.
  Do not put native `required` on an empty draft when committed values already
  satisfy the collection.
- Give every available Tag remove button a localized name that includes its
  value. Canonical Tag preserves native Tab, Enter, Space, disabled, focus, and
  24px pointer-target behavior.
- Pre-mount an empty polite atomic status and update it only with concise add,
  remove, duplicate, capacity, or rejection results. Do not echo keystrokes.
- After a successful add or removal, return focus to the native draft field
  unless a documented target flow has a more logical surviving destination.
- Preserve native punctuation, paste, Backspace, Delete, and IME composition
  behavior unless a target adapter explicitly documents another policy.
