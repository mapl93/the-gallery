## Overview

Account Settings is a passive shell for target-owned account-preference
sections. It provides titled section structure and composition rhythm without
becoming the account schema, Form, customer API, or save lifecycle.

## Presentation

`sections` is the only Account Settings property. Each section supplies a
visible contextual heading, optional description, and target-owned composition
of canonical controls or Forms. Profile fields, display choices, action
labels, ordering, validation, and persistence do not become U9 properties.

The artwork deliberately combines one explicit profile Form with immediate
display-preference Switches. That is fixture content, not a universal inventory.
Each target documents the truthful commitment lifecycle per section. A Form may
wrap only coherent deferred sections; immediate controls remain outside any
unrelated Save action.

## Usage Guidelines

<DoDont>
  <Do>Choose a clear persistence boundary for each target and compose canonical Form and controls without copying their anatomy.</Do>
  <Dont>Do not make U9 claim that every setting saves globally, immediately, or through the same account API.</Dont>
</DoDont>

- Use concise titles and explain consequences before the controls they affect.
- Use Switch only when the binary setting takes effect immediately. Use a
  deferred canonical control when a choice waits for Form submission.
- Treat notification and marketing consent as policy-backed records with their
  own evidence and lifecycle, not as generic immediate booleans.
- Keep field names, autocomplete purposes, validation, pending state, errors,
  consent, and customer-data policy with the owning target and dependency.
- Put target success/failure feedback in the owning Form or adjacent feedback
  component; U9 does not include an empty live region.

## Accessibility

- Render a passive generic root and one native `section` per thematic group.
- Give every section a non-empty visible contextual heading with a unique ID
  and `aria-labelledby`; preserve the heading level required by the page.
- Label every Input and Switch visibly. Preserve native names, values,
  autocomplete, checked state, focus, keyboard, and validation behavior.
- Use a labelled group or Fieldset for related controls and reference relevant
  visible description text.
- Keep immediate Switches outside deferred save semantics. Announce real
  target results with sufficient context only after they occur.
- Link to or omit platform-hosted account settings instead of copying them into
  a neutral flow that cannot preserve the platform lifecycle.
