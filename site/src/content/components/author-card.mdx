## Overview

Author Card is a passive, fail-closed identity composition for exactly one target-supplied article author. It requires one visible name and may add a canonical Avatar, role or affiliation, plain biography, and canonical author Links without fetching data, inferring destinations, exposing provider fields, or becoming the surrounding article landmark.

## Presentation

The shared renderer uses a neutral `.author-card` `div` and neutral `.author-card__name` paragraph because the consuming article owns placement and document structure. A host may wrap L6 in an article `footer`, use a tangential `aside`, choose a contextual heading, or use `address` only for contact-only content whose nearest article/body relationship is truthful.

`full` is the default classless framed presentation and renders every supplied optional part. `compact` adds `.author-card--compact` and renders only Avatar, name, and role; biography and Links are omitted from the DOM rather than merely hidden. A blank `name` removes the complete root. Missing optional content creates no empty wrapper or derived fallback.

The optional Avatar slot carries both canonical `.avatar` and contextual `.author-card__avatar` classes. The target explicitly supplies an image or already-derived initials, semantic Avatar size, and contextual alternative. The optional Links slot uses native `.link.link--nav.author-card__link` anchors; labels, destinations, target/rel security, `rel="author"`, provider choice, and privacy policy remain target-owned.

## Usage Guidelines

<DoDont>
  <Do>Use full presentation when a short biography and author destinations add useful context near one article.</Do>
  <Dont>Do not make the whole card clickable, infer a profile from the name, or publish email, homepage, or social destinations without target policy.</Dont>
</DoDont>

<DoDont>
  <Do>Use compact as a concise identity row and place it in a host-owned byline/header/footer composition.</Do>
  <Dont>Do not supply critical biography or destinations only to compact, because those nodes are intentionally not rendered.</Dont>
</DoDont>

One L6 root represents one person. A target with multiple authors repeats Author Card inside an appropriate semantic list or group; singular L6 does not expose a CMS-specific author collection. Role is visible content, not an ARIA role. Biography is complete plain text in the neutral boundary; rich authoring, sanitization, localization, structured data, analytics, SEO, image delivery, fallback, and social-provider behavior stay with the target.

Full layout responds intrinsically to its available inline size and the Link group wraps. Mobile, Tablet, Desktop, and XL are evidence contexts rather than component sizes or viewport breakpoints. Avatar keeps its own canonical fixed size while Author Card owns only the relationship between supplied parts.

## Accessibility

- Require a non-empty visible author name and omit the root without it; do not create an anonymous region or image-only identity.
- Keep the neutral root out of the landmark and heading outline. The host chooses a truthful `footer`, tangential `aside`, contact-only `address`, contextual heading rank, or linked-name policy.
- Hide adjacent Avatar initials or use an empty image alternative when the visible name already supplies the same identity. Supply contextual alt only when the portrait communicates additional useful information.
- Use native canonical Links with real `href` values for profile, homepage, social, archive, or `mailto:` destinations. Use Button only for an action.
- Add `rel="author"` only when the destination truthfully describes or contacts the nearest article author. Preserve complete localized link purpose, target/rel security, keyboard focus, forced colors, and reduced motion.
- Preserve `dir="auto"` on standalone target strings, complete text at narrow widths and zoom, 200-percent text, user text spacing, and logical RTL flow. L6 owns no live region, keyboard model, focus management, status, loading, announcement, or neutral runtime.

Anatomy: `.author-card`, optional `.author-card__avatar.avatar`, required `.author-card__info` and `.author-card__name`, optional `.author-card__role`, full-only `.author-card__bio`, and full-only `.author-card__links` containing `.author-card__link.link.link--nav` anchors.

Dependencies: canonical [Avatar](/components/avatar) and [Link](/components/link). Runtime Exhibit and Studio resolve the same registered `AuthorCardArtwork`, fixture values, DOM, variant omission, Avatar and Link composition; the markup above is the matching static fallback. Owner decision 50 accepts this singular, neutral, host-owned boundary: multiple authors repeat canonical cards, public email stays off by default, and homepage/social destinations require explicit target supply and approval. The contract remains `pilot`; real target integration, final Full/Compact visuals, Avatar fallback follow-up, L6-specific design evidence, and explicit human stability review remain pending.
