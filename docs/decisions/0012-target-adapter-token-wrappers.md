# 0012. Target Adapter Token Wrappers

Status: Accepted Initial Implementation

Date: 2026-05-23

## Context

The neutral web target is the first stable consumer of `tokens/source/`:

```text
tokens/source/
  -> platforms/web/tokens.css
```

The next question was whether targets such as Shopify and Webflow should consume `platforms/web/tokens.css` directly or through target-specific wrappers.

## Decision

Use the neutral web target as the shared web foundation.

Targets can consume it in two ways:

- Direct consumption for target-neutral web and framework outputs when no platform-specific packaging is needed.
- Thin wrappers for platform targets such as Shopify, Webflow, Framer, and similar environments.

The wrapper should not redefine design decisions. It may own target-specific concerns such as:

- Destination path.
- Asset naming.
- Platform load order.
- Packaging conventions.
- Comments or target metadata.
- Platform-specific overrides that are explicitly documented.

## Shopify Pilot

Shopify is the first wrapper pilot:

```text
tokens/source/
  -> platforms/web/tokens.css
  -> scripts/build-shopify-tokens.js
  -> platforms/shopify/assets/tokens.css
```

`platforms/shopify/assets/tokens.css` is generated from `platforms/web/tokens.css`.

Shopify layouts load it before component CSS:

```liquid
{{ 'tokens.css' | asset_url | stylesheet_tag }}
{{ 'base.css' | asset_url | stylesheet_tag }}
```

`npm run build:tokens:shopify` builds and validates this path.

## Legacy Boundary

`npm run build:tokens` remains the legacy Style Dictionary target build for targets that have not switched yet. It now reads only:

```text
tokens/*_tokens.json
```

Shopify token output is no longer generated by `config.js`; it is generated through the Shopify wrapper path above. Webflow and Framer remain on the legacy token build until they receive their own wrappers or source-token targets.

## Validation

The Shopify wrapper is validated by:

```sh
npm run validate:tokens:shopify
```

The validator checks that:

- `platforms/shopify/assets/tokens.css` includes the generated neutral web target.
- The wrapper exposes current public component-token aliases.
- Shopify layouts load `tokens.css` before `base.css`.

## Consequences

- Shopify is the first platform target to consume the new token architecture.
- The neutral web target remains reusable by future web/framework outputs.
- Legacy token files remain available while Webflow and Framer are migrated later.
- Running `npm run build` now builds Shopify tokens through the new wrapper, legacy Webflow/Framer tokens through Style Dictionary, and copied component assets through the component copy script.

## Follow-Up Work

- Add the Webflow token wrapper using the same pattern.
- Decide whether Framer should wrap `platforms/web/tokens.css`, receive JS/TS output from `tokens/source/`, or both.
- Add target package/release policy once more targets switch from legacy.
