## Usage Guidelines

<DoDont>
  <Do>Use Combobox when users benefit from typing, filtering, autocomplete, or remote results.</Do>
  <Dont>Don't replace a short finite Select with a more complex searchable field.</Dont>
</DoDont>

## Accessibility

- Associate the visible label with the input.
- Keep `aria-expanded`, `aria-controls`, and `aria-activedescendant` synchronized.
- Use `role="listbox"` and non-interactive `role="option"` elements. Options are not Tab stops and cannot contain links, buttons, or other interactive descendants.
- Support Arrow Up/Down, Enter, Escape, and Tab without moving DOM focus from the input or overriding ordinary text-editing keys.
- Highlight is temporary navigation state. It must not replace the selected or arbitrary typed value until the user commits with Enter or pointer selection.
- Authored options are filtered locally. Remote loading, ranking, caching, and virtualization remain target-owned.
- The native text input owns `name`, required validity, FormData, `input`/`change`, and reset; do not add a mirrored hidden value.

## References

### Visual customization

Customize field width, shared Input padding/border/focus/type, popup limits and
spacing, option size/padding, selected weight, check size and empty-message
padding in Studio. Exhibit lists the same public token controls. The standalone
field has no search icon; the owner removed the former Studio-only decoration.

Popup viewport inset limits its maximum width. Keep the field itself within its
container. Default and validation border colors are strengthened with private
60% and 70% primary-text mixes; swatches edit those inputs. The parent Field
Wrapper owns labels and feedback. Filtering, highlight, free text and IME are
behavior, separate from visual customization. Closed-popup positioning remains
private because native `hidden` removes the popup from layout.
