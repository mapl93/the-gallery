## Presentation

## Usage Guidelines

### Visual customization

Studio and the Exhibit reference expose the same 31 public tokens from the contract.
Slider owns track height (4px), thumb size (20px), control height (44px), label and
feedback gap (8px), label-to-value gap (16px), and thumb border width (2px). The
control accommodates the thumb if its configured height is smaller. Keep the
activation area usable when customizing these dimensions.

Shared tokens supply label/value typography, thumb surface, fill, track and thumb
radius, shadow, focus width, validation colors, disabled opacity and transitions.
The track mixes 60% of its border input with primary text; validation fill/border
mixes 70%, and validation label mixes 55%. The inspector labels these as mix inputs.
They are editable source colors, not promises that the resulting color is identical.

Native values determine private progress, lower/upper fill and direction. These
are runtime data, not customization tokens. Centering, pointer routing, native
thumb rendering and forced-color system colors stay in CSS. Before / After keeps
its own composed thumb geometry while inheriting Slider behavior.

Adopt the matching generated CSS, tokens and runtime together in consumer-owned
copies. Updating this repository does not update existing installations. Existing
public aliases remain available; Slider's inventory now names its actual track
border input instead of the unused secondary-surface role.

<DoDont>
  <Do>Always pair form inputs with visible labels for accessibility.</Do>
  <Dont>Don't rely on placeholder text as the only label — it disappears on input.</Dont>
</DoDont>

## Accessibility

<Callout type="tip">
  Use native `input type="range"` for expected keyboard and assistive technology behavior.
</Callout>

- Provide a visible label or equivalent accessible name.
- Expose `min`, `max`, `step`, and current value.
- Keep visible value text synchronized with the input value.
- For dual-handle ranges, keep lower and upper values ordered and announce each handle clearly.
- In range mode, give the lower and upper native inputs distinct form names. Their submitted values and reset behavior remain authoritative.
- Framework adapters may control the native values and consume `input`/`change`; they should not add a mirrored hidden range value.
