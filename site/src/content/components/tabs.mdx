## Overview

Tabs switches among related peer panels in one local context. The horizontal set
has one accessible name, one selected tab, roving focus, and one visible panel.

## Usage Guidelines

<DoDont>
  <Do>Use Tabs for related, preloaded content panels at the same hierarchy level.</Do>
  <Dont>Don't use Tabs for primary navigation, sequential steps, form choices, or unrelated destinations.</Dont>
</DoDont>

Use automatic activation only when a focused tab can reveal its preloaded panel
without noticeable latency. Use manual activation when selection requires Enter
or Space. Vertical, closable, reorderable, routed, lazy, and responsive Accordion
modes are outside the v1 contract.

## Accessibility

<Callout type="warning">
  Styling alone does not create Tabs. The target must coordinate selection,
  roving focus, ids, keyboard events, hidden panels, and one change event.
</Callout>

- Label the `tablist` and connect each `tab`/`tabpanel` pair with
  `aria-controls` and `aria-labelledby`.
- Keep exactly one enabled tab selected and one panel visible.
- ArrowLeft/ArrowRight wrap among enabled tabs; Home/End move to the first/last
  enabled tab. Manual mode waits for Enter, Space, or click to select.
- Include a text-only panel in the Tab sequence when it has no appropriate first
  focusable descendant.
- Skip disabled tabs and preserve visible focus independently from selection.

## Visual Customization

Twenty-two public roles cover appearance and geometry. Track and selected-indicator thickness share one token, initially 2px; the track is painted inside the scrollable list so the selected border stays visible on the same line. The former negative margin put that border outside the scroll clip. Tab block/inline padding factors start at 0.5/1 and panel block/inline factors at 1/0, each relative to the shared responsive spacing base. Tab weight reuses medium. Focus width starts at 2px for tab and panel, with independently editable tab inset and panel outward offset of 2px.

Selected text retains its existing 70% accent plus 30% primary mix, while the indicator uses the accent input directly. Both inputs remain editable and Studio names their roles; changing one input does not promise an exact resulting text color. The shared minimum target bounds tab height. Wide text uses the existing horizontally scrollable tablist; roving focus, activation, disabled state, panel visibility and RTL navigation remain behavior responsibilities.

Forced colors use a system-color border for the track because gradients are suppressed; this adds one token-width to the list height in that mode while keeping the selected border visible.

The Studio Details-selected control reflects that item after pointer or keyboard selection. Turning it on selects Details; turning it off selects the Overview fixture. Selecting Shipping directly remains Shipping while that item-level control is false.
