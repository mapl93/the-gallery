## Overview

Glaze Guide presents the accepted passive `R2-A` target-owned collection of named glaze samples and optional featured reference detail. It supplies durable document structure, not a glaze schema, form control, product-option selector, filter, chemistry authority, claim service, or synchronization runtime. Purchasable glaze choice composes canonical Radio or Variant Selector outside R2.

## Presentation

The required `swatches` slot supplies one or more complete passive samples in target-owned source order. `title` and `detail` are optional. With a title, the root is a named native section; without one, it is a generic container with no dangling labelling relationship.

Each item is one native list item containing a self-contained sample figure. Its visual, visible name, and figure caption are required; the target-formatted code is optional. The visible name remains the record identity even when the sample visual has an appearance description.

Optional detail is a separately named passive article. It must be explicitly framed as featured or reference content and may contain contextual media plus native term/value facts. It is not implicitly selected and does not update from neutral sample interaction.

The demonstrated records, codes, appearance descriptions, editorial image, facts, heading levels, and count are fixture content, not defaults or a public glaze-record schema.

### Behavior boundary

Glaze Guide owns no controlled/uncontrolled value, event, selection, hover state, focus management, navigation, filter, form submission, persistence, live announcement, or detail synchronization. The legacy `[aria-selected="true"]` selector remains a target CSS hook under ADR 0083; it is not permission to use `button[aria-selected]` without a complete widget pattern.

If a target makes samples mutually exclusive product choices, compose canonical Radio or native radios. Define the labelled group, `name`, values, checked/default-checked state, change event, disabled/required/validation behavior, keyboard model, and detail synchronization in that target contract before implementation. Use listbox only when the product truly needs listbox semantics and focus behavior.

### Responsive behavior

The collection and detail respond to their actual host width through intrinsic grids. Text remains complete and wraps in localized, RTL, unbroken, zoomed, and user-spaced conditions. Passive samples own no motion.

## Guidelines

<DoDont>
  <Do>Pair every visual sample with a concise visible name, a truthful appearance description when useful, and a target-formatted code only when it has an owned source.</Do>
  <Dont>Do not infer selectable behavior, glaze chemistry, product compatibility, safety, food-contact status, or a CMS schema from the sample and detail selectors.</Dont>
</DoDont>

- Keep target-authored records in a meaningful, documented source order.
- Use detail only when it is explicitly featured/reference content or when an approved target interaction can keep it synchronized.
- Use complete native `dt`/`dd` groups for supplied facts and do not invent vocabulary, units, or claims.
- Use media only when it contributes useful context. Describe the actual visual rather than calling generic editorial photography a glaze test tile.
- Omit incomplete records and omit the complete Glaze Guide when no valid samples remain.
- Keep loading, empty, error, search, grouping, pagination, formulas, claims, localization, product-option mapping, inventory, and analytics in the target layer.

## Accessibility

- Use a contextual visible heading when the guide is a thematic page section. Untitled compositions remain generic containers.
- Preserve native `ul > li > figure > figcaption` structure and keep each sample's name visible.
- Keep names and essential facts textual; never rely on color, finish, texture, image, or code alone.
- Give informative visual/detail media context-specific alternatives. Use `alt=""` for decorative or fully redundant images.
- Name optional detail articles from their visible heading and preserve native description-list term/value relationships.
- Do not add `grid`, `listbox`, `option`, `radio`, `button`, tabindex, roving focus, selected state, or live announcements to the passive collection.
- An approved selectable target must implement the complete canonical Radio/native-radio or other accepted widget contract, including keyboard and visible focus.

## Specification

**Dependencies:** None for the passive neutral implementation. An approved mutually exclusive target mode should compose canonical [Radio](/components/radio).

**Anatomy:** conditional `.glaze-guide` section/div; optional header and title; required native `.glaze-guide__grid`; repeated native `.glaze-guide__item`; one passive `.glaze-swatch` figure with required visual/caption/name and optional code; optional named `.glaze-detail` article with media, information, required name, and native term/value groups.

### Targets

- **Neutral Web:** conditional native section/div, list/items/figures, optional named detail article/description list, intrinsic CSS, and zero R2 JavaScript.
- **Shopify:** planned until record source, editor schema, passive versus selectable use, product-option mapping, claim policy, ordering/limits, localization, and first consumer are approved.
- **Webflow / React / Angular:** preserve passive semantic children. A future selector composes canonical Radio and declares state/events rather than mutating the passive figure.
- **Figma / native targets:** separate passive reference and selectable-control concepts; generic registered Figma nodes are not visual approval.
