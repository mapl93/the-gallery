## Overview

Labelled, horizontally contained sequence for target-supplied review pagination controls. The neutral component provides presentation, not a paging algorithm.

## Presentation

The required root is preferably a labelled nav. Optional list and item wrappers contain required repeated native controls and an optional passive ellipsis. Controls expose default, hover, focus-visible, current, and unavailable presentation while the sequence remains horizontally reachable.

Targets choose native links for URL navigation or native buttons for an in-place strategy. They also supply previous, numbered, omitted, and next controls, including current and unavailable state.

## Usage Guidelines

<DoDont>
  <Do>Choose native links or buttons only after the target pagination strategy and destination behavior are defined.</Do>
  <Dont>Do not infer page windows, URL state, loading, scrolling, focus movement, or result updates from the CSS sequence.</Dont>
</DoDont>

Numbered pages, cursor or offset pagination, load more, infinite loading, provider-managed navigation, and every synchronization behavior remain open target decisions. The preview demonstrates native button anatomy only; it does not implement paging.

## Accessibility

<Callout type="info">
  The navigation label distinguishes review pagination from other page navigation.
</Callout>

- Use a `<nav>` with a specific accessible label.
- Prefer anchors for URL navigation and buttons only for a target-owned in-place flow.
- Mark exactly one numbered control with `aria-current="page"` when the strategy exposes page numbers.
- Give previous and next controls directional accessible names.
- Use native `disabled` for unavailable buttons.
- Do not leave `aria-disabled` links activatable; omit their destination and prevent every input modality according to the selected target pattern.
- Keep the control sequence keyboard reachable when it overflows horizontally.
