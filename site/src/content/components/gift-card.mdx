## Overview

Gift Card presents target-formatted amount and balance strings, a selectable code, optional copy action, target-owned actions, optional QR media, and an optional workflow-neutral form. It does not calculate commerce data or define purchase, redemption, wallet, print, or balance-lookup behavior.

## Presentation

Visual media, target-formatted amount, page heading, code wrapper, and selectable code are required. Brand text, supporting message, copy action, balance, action group, QR media, and form are optional. The visual may include a readable overlay, while the amount and balance remain target-formatted strings rather than calculated values.

The artwork's form is a workflow-neutral preview fixture. It composes a complete Input with visible label, control, native field, associated message, fixed Warning indicator, and no `aria-invalid`. Default, Error, Success, and Warning remain Input variants, and the submit action composes Button semantics. The form purpose, endpoint, pending state, and response lifecycle remain target-owned.

## Usage Guidelines

<DoDont>
  <Do>Display the exact code and target-formatted commerce strings supplied by the issuing target.</Do>
  <Dont>Do not infer balance lookup, redemption, purchase, wallet, print, or account behavior from this page.</Dont>
</DoDont>

- Keep the code selectable even when a copy action is also supplied.
- Name target-owned actions by their actual target behavior.
- Explain the purpose of QR media without exposing its payload as the only usable representation.
- Treat the artwork amount, balance, code, form field, and action as preview fixtures, not component defaults.

## Accessibility

- Keep the gift-card code selectable and expose a clearly named native button when copying is supported.
- Announce copy success or failure without relying on icon or color change alone.
- Provide useful alternative text for meaningful gift-card imagery and explain the purpose of QR media.
- Give amount and balance strings clear currency context.
- Every composed Input retains its visible label, control, associated message, and Default, Error, Success, and Warning semantics.
- Reserve `aria-invalid="true"` for Error; Success and Warning use descriptive messages without `aria-invalid`.
- Keep target-owned actions native, keyboard accessible, visibly focused, and clearly named.
