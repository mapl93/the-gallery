## Overview

Control-agnostic composition for a visible label, one canonical control, helper text, and one current feedback message.

## Presentation

Field Wrapper presents `default`, `error`, `success`, and `warning` feedback families without taking ownership of its composed control's value, validity, events, or reset.

## Usage Guidelines

<DoDont>
  <Do>Compose one canonical control and reference only the helper/current feedback that exists.</Do>
  <Dont>Don't use the generated required marker without synchronizing native required state.</Dont>
</DoDont>

## Accessibility

- Associate labels with controls using matching `for` and `id` values.
- Reference helper and feedback messages with `aria-describedby`.
- Use `aria-invalid="true"` only for error feedback.
- Keep order predictable: label, canonical control, helper, current feedback.
- Let the composed control own value, disabled, validity, events, reset, and controlled/uncontrolled behavior.

## References

### Visual customization

Label gap and Message gap reuse Input's public 4px defaults independently. The
canonical child root carries `.field__control`, which removes the child's exterior
margin so the wrapper does not double the space below the control. Helper text
and the one current feedback each use the message gap. The parent owns spacing
between complete fields.

Studio also exposes label/message size, line height and weight, family, required
marker, feedback colors and the optional error icon's size, gap and top offset.
Default supports a neutral feedback message; empty feedback stays absent in every
variant. Error icon controls appear with the Error fixture.

Validation label/message colors mix 55% of the selected feedback color with
primary text; the swatches are inputs to this derivation. Icon paths, flex flow,
wrapping and system colors remain implementation details. On update, migrate any
wrapper-only override of `--space-input-margin-bottom` to the two gap tokens;
that legacy alias still controls standalone Input's exterior margin.
