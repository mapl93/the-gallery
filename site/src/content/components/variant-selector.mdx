## Overview

Variant Selector composes one or more product-option groups from native radios.
The visual mode may use named swatches or text pills; the browser remains the
owner of selection, keyboard behavior, form data, validity, events, and reset.

## Presentation

Every group has a stable visible option name and a derived visible selected value.
Swatches keep a 44px target around a 36px color or image surface; pills keep the
same minimum target and wrap from the component's available inline size. Selected,
keyboard-focus, commercially unavailable, and native-disabled states remain
visually distinct in light, dark, and forced-color environments.

Swatch fill is target data, not a design token. The target may supply a color or
image, but every swatch still needs a localized text name. The selected-value text
is a projection of the checked radio, never a second editable value owner.

## Usage Guidelines

<DoDont>
  <Do>Render each product option as one native `fieldset`/`legend` with same-name radios, one initial checked value, localized option names, and explicit unavailable text.</Do>
  <Dont>Do not add `radiogroup` roles, independent checked booleans, handle-derived colors, or an all-variants data engine to the neutral component.</Dont>
</DoDont>

Under accepted direction D4-A, commercial unavailability and native `disabled`
are separate states. Sold-out values remain selectable so the target can explain
their state, project truthful information, or offer Back In Stock. Nonexistent
combinations and genuinely unusable values are natively disabled. Selection never
makes unavailable merchandise purchasable. A parent commerce coordinator owns cross-group combination lookup,
variant id, URL, Price, media, inventory, selling plan, submit state, and at most
one localized product-update announcement.

## Accessibility

<Callout type="tip">
  Native radios already provide the expected one-stop group focus, Arrow and Space
  behavior, `input`/`change`, required validity, FormData, and form reset.
</Callout>

- Use a first native `legend` to name each `fieldset`; do not recreate the Radio
  Group APG pattern with ARIA and JavaScript around native radios.
- Give every option a non-empty localized label independent from its color,
  image, tooltip, selected state, or availability mark.
- Hide only the redundant derived selected-value fragment from the accessible
  group name. Keep the stable option name visible and exposed.
- Pair unavailable styling with associated localized text and a non-color cue.
  Do not use opacity, strikethrough, or native disabled state as the only status.
- Preserve a target of at least 44 by 44 CSS pixels and separate visible selected
  and `:focus-visible` indicators at 200% zoom and in forced colors.
- A controlled framework adapter binds one group value. Static HTML uses
  `checked` only for its initial uncontrolled value.

## References

### Target translation

- Neutral Web: canonical CSS plus authored native markup; no base JavaScript.
- Shopify: render `product_option_value.selected`, exact associated variant,
  stable ids, native swatch color/image, and option-value ids. The Main Product
  coordinator performs high-variant Section Rendering and follows
  `product_url` when a Combined Listing value points to a sibling product.
- React and Angular: one controlled `value` or uncontrolled `defaultValue` per
  group with native change semantics.
- Figma and future native targets: preserve group label, option label, checked,
  unavailable, and disabled concepts without copying DOM-specific internals.
