## Overview

Native form composition with sections, container-responsive rows, explicit canonical actions, and an optional linked error summary.

## Presentation

Form arranges canonical Field Wrapper and Button children without taking ownership of their values. One-, two-, and three-column intent responds to the form container and never changes source, reading, or tab order.

## Usage Guidelines

<DoDont>
  <Do>Keep controls named, source and visual order aligned, and native validation enabled unless the target owns a complete accessible replacement.</Do>
  <Dont>Don't turn the base Form into an async request client, validation schema, or controlled value object.</Dont>
</DoDont>

## Accessibility

- Use a real `<form>` on Web so named controls, activated submitter, validation, `FormData`, and reset remain native.
- Use explicit submit, reset, and non-submit button types.
- Link error-summary items to invalid fields and associate each field with its inline feedback.
- Let the target decide when to insert or announce the summary and whether to focus it or the first invalid control.
- Keep responsive columns from changing source, reading, or keyboard order.
