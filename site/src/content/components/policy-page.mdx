## Overview

Policy Page presents a page title, optional visible update date, optional table of contents, and one required semantic legal-content slot. The target supplies the document structure and content; the component does not define a CMS schema, revision model, localization pipeline, policy inventory, or source API.

## Presentation

The root, header, page-level title, and semantic body are required. A target-formatted visible update date and a table of contents with its own title, ordered list, and in-page links are optional.

The body is one semantic document slot. It preserves target-supplied headings, paragraphs, lists, links, tables, media, dates, quotations, code, and stable section identifiers. The artwork is a documentation fixture and does not establish a policy type, required clause, or content source.

## Usage Guidelines

<DoDont>
  <Do>Preserve the legal document's semantic structure and source order.</Do>
  <Dont>Do not turn preview content into a shared CMS schema, revision system, or policy inventory.</Dont>
</DoDont>

- Keep table-of-contents links in the same order as their target sections.
- Use stable, unique in-page identifiers when a table of contents is supplied.
- Let the target format visible dates and provide exact machine-readable values when available.
- Preserve horizontal keyboard access when wide tables or code blocks overflow.

## Accessibility

- Use one page-level title followed by a logical, non-skipping heading hierarchy.
- Render the optional update date as visible text and use `<time datetime>` when the target supplies an exact value.
- Place the optional table of contents in a labelled navigation landmark.
- Keep every table-of-contents link paired with a unique section identifier in the same document.
- Preserve semantic lists, tables, links, quotations, media alternatives, and other structures from the target source.
- Keep long text, media, tables, and code contained at narrow widths without removing keyboard access to overflow.
