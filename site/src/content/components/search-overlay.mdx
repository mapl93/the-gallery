## Overview

Search Overlay presents a native search field and optional target-owned result content in a full-screen surface. It exposes open presentation without choosing a search provider or overlay controller.

## Presentation

The artwork uses documentation-owned trigger and close controls to exercise `.is-open` inside a contained stage. Those controls are fixture behavior, not Search Overlay anatomy or public properties. At runtime, `open` must also keep the visible class and accessible hidden state synchronized.

`inputLabel`, `query`, and optional `placeholder` map to the native search input. `results` is one optional target-owned region that may contain result, loading, empty, or error content. Endpoints, ranking, debounce, result records, price formatting, and announcements are not component defaults.

## Usage Guidelines

<DoDont>
  <Do>Keep the field label useful and let the target render truthful loading, empty, error, or result content.</Do>
  <Dont>Do not treat fixture products, prices, ranking, or query timing as Search Overlay API.</Dont>
</DoDont>

- Keep placeholder text supplemental to the accessible label.
- Use native links for navigable results.
- Keep provider, cancellation, caching, and analytics policy in the consuming target.

## Accessibility

- Provide `inputLabel`; placeholder text does not replace an accessible name.
- Keep `aria-hidden` synchronized with the visual open state.
- The target overlay runtime must provide a named dismissal action, focus entry, `Escape` handling, focus restoration, and any required scroll locking.
- Announce changing result status according to an accepted target policy without excessive live-region output.
- Give informative result media useful alternative text; hide decorative thumbnails from assistive technology.
