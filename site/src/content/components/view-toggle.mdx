## Overview

Grid / List View Toggle is the fixed two-value collection presentation choice.
It composes canonical Segmented Control so the browser owns one native Radio
value, one Tab entry point, logical arrow navigation, form data, events, disabled
propagation, and reset. The neutral component requests a mode; the target owns
the actual results, preference lifecycle, and any useful announcement.

## Presentation

E5 follows the owner-provided direction: one joined pill-like surface, Grid and
List as equal segments, a fixed decorative icon plus visible text in each, and
an unambiguous active surface. The reference establishes hierarchy and
interaction, not exact final colors or dimensions.

The Fieldset keeps a visible Legend. The two segments remain horizontal and
share available width; localized text can wrap at narrow sizes without becoming
icon-only. Canonical Segmented Control supplies the 44px minimum target,
selected/hover/focus/disabled states, dark mode, forced colors, and reduced
motion. E5 adds only profile width, pill radius, icon gap, and icon/text
containment.

The visual surface is not the state owner: the checked native Radio is. There
are no pressed Buttons, `aria-pressed` mirrors, custom roles, roving tabindex
runtime, or E5 keyboard listener.

## Usage Guidelines

<DoDont>
  <Do>Render E5 only when both Grid and List are real, useful presentations of the same current results.</Do>
  <Dont>Do not reset filters, sort, pagination, product identity, or selection merely because the presentation changes.</Dont>
</DoDont>

- Keep exactly two fixed values in stable source order: `grid`, then `list`.
- Grid is the neutral initial value. A target may initialize List only from an
  explicit valid merchant, URL, or account preference.
- Omit the component when only one meaningful layout exists or the target cannot
  coordinate both result modes truthfully.
- Keep Grid and List as visible localized text. The fixed icons are redundant
  visual cues and are never public icon choices.
- Apply the selected mode to the existing result owner. Preserve filters, sort,
  pagination, and product identity; decide URL, scroll, focus, analytics, and
  persistence in that target.
- Neutral E5 stores nothing and creates no live region. A target may update one
  pre-existing localized result status only when the mode change produces a
  meaningful result presentation update.
- Shopify needs an owning collection section, translated labels, merchant/default
  policy, result mapping, optional URL/persistence coordination, editor behavior,
  and live-store proof before it is target-ready.

## Accessibility

- Preserve the canonical native Fieldset, visible Legend, and exactly two
  same-name Radios. Do not add redundant `radiogroup`, `radio`, Button, or
  `aria-pressed` semantics.
- Keep exactly one checked value. Native Tab enters/exits the group; logical
  arrows move focus and selection; Space selects the focused value.
- Keep the Grid/List text visible and complete. Hide decorative icons with
  `aria-hidden="true"`; icon, order, color, or selected surface never supplies
  unique meaning.
- Native Radios retain `input`/`change`, FormData, disabled propagation, and
  reset. Controlled framework adapters project one value, not two booleans.
- Keep focus on the selected segment unless the owning result workflow has a
  separately reviewed focus policy.
- Preserve 44px targets, effective 200% text, user text spacing, RTL, dark mode,
  reduced motion, forced colors, and narrow-container wrapping.

Static and uncontrolled Web markup authors one initial `checked` Radio.
Controlled adapters project one `activeView` and one change callback. Both use
the same native value and result-coordinator boundary.
