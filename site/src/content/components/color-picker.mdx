## Overview

Fieldset-and-radio color choice group with named swatches and non-color selection cues.

## Presentation

Color Picker supports `default`, `error`, `success`, and `warning` validation families independently of swatch size and selected state.

Studio and Exhibit expose the same public visual controls: legend and color-name
spacing, row/column gaps, the three fill sizes, minimum target, borders, selected
ring gap/width, check size, focus geometry, label width, typography, colors and
motion. Defaults keep 24/32/40px fills and at least 44px activation targets.
Changing a fill does not shrink its native activation target.

Swatch fills are authored option data, such as a product's glaze color or image;
they are not brand tokens. The optional check uses a fixed icon path and stroke.
Default borders mix the public subtle border at 60% with primary text; validation
borders use 70% of the corresponding field border and labels use 55% of the field
label. Their controls edit those inputs. Hover and selected boundaries preserve
the validation family; custom colors still need contextual contrast review.

## Usage Guidelines

<DoDont>
  <Do>Use one visible legend for the question and one visible name for every color.</Do>
  <Dont>Don't use the fill color or optional checkmark as the only selected-state cue.</Dont>
</DoDont>

## Accessibility

<Callout type="tip">
  Color swatches are backed by native radio inputs for single-choice product options.
</Callout>

- Provide an accessible color name for every swatch.
- Do not communicate selected state only by color.
- Keep focus-visible state visible around the selected swatch.
- Let the named native radios own arrow keys, Space, form value, validation, and reset.
