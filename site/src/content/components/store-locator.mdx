## Overview

Store Locator is the general branch-discovery companion to Pickup Location Selector. It searches target-supplied galleries, studios, or stores without requiring product context and presents branch identity, address, hours, services, contact details, and an explicit target-owned directions Link. It never chooses a transaction pickup location or stores a preferred branch.

## Presentation

Store Locator reuses the same canonical manual-search controls, result lifecycle, spacing, record surface, container response, and optional map boundary as Pickup Location Selector. Its result list is informational rather than a Radio group: each native list item contains a named branch article and optional canonical contact or directions Links.

The complete list is always the primary interaction surface. A synchronized map can supplement spatial context but cannot hide branch details, contact, or directions actions behind pins.

## Usage Guidelines

Shared Location Search tokens control spacing, record/map-slot borders and
padding, status geometry and heading weight. These roles belong to the existing
shared anatomy, not another component. Typography aliases remain connected to
the system. Input, Button, Radio and Link retain their own complete APIs.
The optional map engine, tile style, pins and data remain target-owned; the
Studio map illustration is fixture presentation, not a public token surface.


<DoDont>
  <Do>Use Store Locator to discover and inspect branches without requiring a product or transaction.</Do>
  <Dont>Do not use it to choose checkout pickup, persist a preferred store, or trigger location permission automatically.</Dont>
</DoDont>

- Keep manual address, city, region, or postal-code search available in every target.
- Use real descriptive target-owned destinations for phone and directions. The target owns navigation, external-app policy, analytics, and failures.
- Omit absent hours, services, or contact fields cleanly; retain stable name and address for each valid branch.
- Use Pickup Location Selector when selection must emit pickup intent for the current product, variant, and market.

## Accessibility

- Name the surface, search field, search action, and results region visibly.
- Render branches as a native list of named articles with semantic `address` content and ordinary canonical Links.
- Use one coherent status channel for loading/result/empty changes and an alert only for a new error.
- Preserve manual search when geolocation is unsupported, denied, times out, or errors. Permission follows only the explicit localized action.
- Keep all results, details, contact, and directions usable without a map and under keyboard, zoom, RTL, text-spacing, forced-color, and reduced-motion modes.
- Do not add Radios, selected states, preferred-store mutation, or transaction semantics to this discovery surface.
