## Overview

Bottom Navigation is a fixed mobile destination list with visible labels, optional decorative icons, current-page state, and optional target-owned counts.

## Presentation

The root is fixed by canonical CSS on narrow viewports; the documentation helper contains it as the artwork. One `.bottom-nav__list` contains `.bottom-nav__entry` items and native `.bottom-nav__item` links with required visible labels, optional decorative icons/counts, and target-owned current-page state.

Destinations, item count, order, icon source, badge values, and body-offset policy are target responsibilities rather than component defaults.

## Usage Guidelines

<DoDont>
  <Do>Reserve the limited mobile space for persistent, high-priority destinations with visible labels.</Do>
  <Dont>Do not use badges or active color as the only way to identify a destination or state.</Dont>
</DoDont>

- Keep the destination set stable enough to build user recognition.
- Use compact counts only for concise target state that can remain synchronized with the containing link name.
- Coordinate page-bottom spacing in the consuming layout so content is not obscured.

## Accessibility

- Provide the required accessible navigation `label`.
- Keep a visible text label for every item, even when an icon is present.
- Use `aria-current="page"` for the active destination.
- Hide decorative icons and visual count text from duplicate name calculation; include count meaning in the link's accessible name.
- Preserve normal Link keyboard behavior; do not use tablist/menu/toolbar roles or arrow-key handling.
- Announce dynamic count changes only according to target policy and preserve safe-area spacing and the 44px touch target.
