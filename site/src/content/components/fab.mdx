## Overview

Floating icon-only button for a persistent page-level action such as returning to the top of a long page.

## Presentation

FAB has one circular size and one classless variant. It is hidden by default; target-owned scroll or contextual logic composes `.fab--visible` when the action becomes relevant.

## Usage Guidelines

<DoDont>
  <Do>Use FAB for one high-value page action that benefits from persistent placement.</Do>
  <Dont>Do not make it the only way to complete critical navigation or expose several competing FABs.</Dont>
</DoDont>

The target owns the visibility threshold, click result, scroll behavior, safe-area or fixed-chrome collision handling, and any page-state synchronization. A Back-to-Top target must also disable smooth scrolling when reduced motion is requested.

## Accessibility

<Callout type="info">
  Hidden FAB is removed visually with `visibility: hidden`; visible FAB remains a native named button.
</Callout>

- Provide a concise accessible name that describes the action.
- Hide the decorative icon from assistive technology.
- Keep the action reachable by keyboard only while visible.
- After the exit transition completes, the hidden base state is excluded from focus by `visibility: hidden`.
- Respect reduced-motion preferences for its visibility transition.
- Use native `disabled` only when a visible action is temporarily unavailable.

The canonical web source uses a physical bottom-right offset. Logical-end placement and safe-area offsets remain target/visual review decisions rather than additional component properties.

## Visual Customization

Studio and Exhibit expose all 21 public visual roles. Control/icon size start at 48/24px. Bottom and right offsets start at 24px; hidden vertical displacement starts at 8px. These values, border width and focus geometry are public tokens alongside existing colors, radius, shadow, layer and motion.

Studio contains the FAB in a local frame and applies the same offsets there; the installed component remains fixed to the viewport. Physical bottom-right anchoring stays unchanged in RTL. Safe areas, fixed chrome and application scroll/focus behavior belong to the consumer. Editing an offset does not configure those policies. Reduced motion removes interpolation; hidden still uses visibility to exclude focus.
