## Overview

Gift Card presents an already-issued card through a required issuer, target-formatted remaining balance, visible heading, use instructions, labelled selectable code and optional target capabilities. It does not sell, redeem, refresh, associate, print, store, or calculate the card.

## Presentation

Issuer, balance, heading, instructions, code label, and code are required non-empty content. The card surface is always present; optional media is decorative and never becomes the only source of issuer or balance information. Details, actions, QR media, copy, and the pilot form slot are independently optional.

The default review fixture shows issued-card content, target details, one real destination, and a QR placeholder with visible purpose text. It does not show the pilot form because no universal balance-check, purchase, or redemption workflow has been accepted. Enabling that slot in Studio demonstrates native Input/Button composition only and never claims a commerce request.

## Usage Guidelines

<DoDont>
  <Do>Render exact issuer, formatted balance, instructions, and code supplied by the issuing target.</Do>
  <Dont>Do not infer balance freshness, redemption, purchase, wallet, printing, account association, or a form endpoint from P2.</Dont>
</DoDont>

- Keep the code selectable even when a copy Button is present.
- Use a visible copy label and report success or fallback through the pre-existing status region.
- Name every target action by its actual behavior and use anchors for navigation.
- Give QR media visible purpose text while preserving the readable code as the equivalent path.
- Treat all displayed values, status facts, QR content, and destinations as fixtures until a target supplies real data.

## Accessibility

- Omit the component if issuer, balance, heading, instructions, code label, or code is empty.
- Preserve one visible document `main`; this component is a labelled contextual section inside Exhibit and Studio.
- Keep optional artwork decorative with empty alternative text because the required content remains textual.
- Use native `code` text, preserve selection, and compose the copy control from canonical Button.
- Keep the copy status node present before activation and update it politely without moving focus.
- Use canonical Button for all actions; navigation remains an anchor and non-navigation remains a button.
- Keep QR graphics assistive-hidden when the same code is visible, and explain their purpose in a visible caption.
- Any target form keeps a visible Input label, serializable field name, native required validation, and truthful response text.
