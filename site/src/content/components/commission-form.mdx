## Presentation

The preview uses fixture fields to show the complete composition boundary: Input owns label, control, native field, message, and Error validation; Textarea composes Input anatomy and Success validation; File Upload owns its native file input, visible instructions, accepted-type guidance, and Warning validation; Button owns action emphasis and native action semantics. Default, Error, Success, and Warning remain dependency variants, never Commission Form states.

`fields` is required. `title`, `intro`, `referenceUpload`, and `actions` are optional. The target chooses the native form boundary and owns field inventory, consent, submission, persistence, response messages, notifications, and later workflow stages.

## Guidelines

<DoDont>
  <Do>Compose canonical fields, upload controls, and buttons inside the dedicated layout regions.</Do>
  <Dont>Do not add validation classes, messages, drag behavior, busy behavior, or submission state to the Commission Form root.</Dont>
</DoDont>

- Keep every visible label and message owned by its field dependency.
- Use `aria-invalid="true"` for Error only; Success and Warning remain valid unless native validity says otherwise.
- Associate supporting and validation messages with `aria-describedby`.
- Keep file drag-and-drop an enhancement to the native file input.

## Accessibility

- Use a native form when the target provides submission.
- Associate every composed field with a visible label or visible upload instruction.
- Pair Error with `aria-invalid="true"` and corrective feedback; announce dynamically presented errors appropriately.
- Preserve Textarea resize and native value behavior.
- Preserve File Upload accepted-type guidance, keyboard focus, disabled behavior, and selected-file announcements.
- Preserve Button disabled and busy semantics, and announce target-owned submission outcomes without unexpected focus movement.

**Dependencies:** [Input](/components/input), [Textarea](/components/textarea), [File Upload](/components/file-upload), and [Button](/components/button).
