## Overview

Address Form is an authenticated form wrapper that composes target-owned Input and Select fields with optional actions. Its field region supports responsive two-column rows without redefining the child controls.

## Presentation

`fields` is the required slot for Input and Select dependencies. Field labels, names, values, validation, autocomplete, locale-specific ordering, and requiredness remain owned by those controls and by the target address model.

`actions` is optional and can compose submit and cancellation behavior. The repeated fields in the artwork are a fixture. `.address-form__row` only supplies responsive layout and does not create a separate field API.

## Usage Guidelines

<DoDont>
  <Do>Use native autocomplete values and arrange fields according to the address locale.</Do>
  <Dont>Do not duplicate Input or Select validation properties on Address Form.</Dont>
</DoDont>

- Ask only for fields required by the target and destination locale.
- Let Input and Select preserve their own default, error, success, and warning semantics.
- Keep action labels explicit about whether the address is created or updated.
- Submit address mutations through the target account API and reconcile only after its response.

## Accessibility

- Protect address editing behind the target authentication system.
- Associate every field with a visible label and appropriate autocomplete value.
- Connect field-level help and validation messages with `aria-describedby`.
- Move focus to the first invalid field after a failed submission.
- Preserve native form submission and clear keyboard order through responsive rows.
