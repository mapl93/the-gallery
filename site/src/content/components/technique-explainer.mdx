## Presentation

The required `steps` slot supplies one or more complete target-owned records in meaningful authored order. Every step requires a stable identity, non-empty visible name, and complete explanation. `title`, target-composed step `details`, and step media are optional. Details may contain applicable reviewed materials, duration, temperature, tools, or other native content without defining universal fields.

With a title, the root is a named native section; without one, it is a generic container with no dangling label relationship. The sequence is one native `ol` with direct `li` items. The visible zero-padded number is derived presentation and is hidden from assistive technology because the ordered list already supplies programmatic sequence.

Step text always precedes optional supporting media in DOM order. Wide component containers may alternate which inline side contains the media; narrow containers stack text then media. The authored step order and reading sequence never change.

The demonstrated names, descriptions, working note, photos, alternatives, heading levels, number format, count, and alternation threshold are fixture/presentation details, not defaults or a public process-record schema. Safety warnings and precautions belong in separately reviewed rich content or canonical Alert composition, never an arbitrary untyped detail.

### Behavior boundary

Technique Explainer owns no controlled/uncontrolled value, current step, completion state, selected state, event, focus, keyboard model, navigation, disclosure, request, timer, persistence, live announcement, or analytics.

If a product needs an interactive workflow, compose a separate canonical component whose semantics match the behavior: Steps for current/completed task state, Progress for measurable completion, Tabs/Accordion for controlled visibility, or native Links/Buttons for navigation/actions. Do not add those roles and states to passive R3 without a new accepted product and architecture decision.

### Responsive behavior

Canonical R3 CSS establishes a named inline-size container. Narrow hosts use one column in text-then-media order. Wider hosts use two columns and alternate only the supporting media side for even steps. Logical properties preserve RTL flow, and complete text wraps without clamping.

## Guidelines

<DoDont>
  <Do>Write steps that remain complete and understandable from their visible text and ordered source sequence.</Do>
  <Dont>Do not use alternating layout, imagery, or decorative numbers as the only expression of order, instruction, current state, or completion.</Dont>
</DoDont>

- Keep names action-oriented and explanations concise but complete.
- Preserve meaningful authored order and omit incomplete records.
- Use media only when it contributes useful context; make the media and alternative agree with the actual step.
- Use `alt=""` for decorative or fully redundant images. Use a concise contextual alternative when media adds information.
- Keep loading, error, branching, safety review, editorial revision, localization, workflow controls, persistence, and analytics in the target layer.
- Use a separate semantic composition for unordered phases, parallel work, optional branches, live progress, or navigation.

## Accessibility

- Use a contextual visible heading when the explainer is a thematic page section. Untitled compositions remain generic containers.
- Preserve native `ol > li` structure and meaningful authored item order.
- Keep every step's required name and explanation visible and complete.
- Treat the large visual number as redundant presentation; native list semantics remain the accessible sequence.
- Keep step text before media in DOM order and do not create a conflicting visual sequence.
- Give informative media truthful context-specific alternatives and decorative/redundant images empty alternatives.
- Do not add `progressbar`, tabs, disclosure, button, link, `tabindex`, `aria-current`, selected/completed state, roving focus, or live regions to passive neutral R3.

## Specification

Public visual tokens expose step padding, independent ordinal/name/details gaps, divider thickness and wide text share after the grid gap. Existing wide alternation is preserved, including the half-width text-only step until the owner resolves that visual choice. Padding factors use the shared grid gap; text/content gaps use the shared element gap. Studio and Exhibit derive controls from the same public inventory.


**Dependencies:** None for the passive neutral implementation. A future interactive workflow composes a separate accepted canonical contract rather than expanding R3 by implication.

**Anatomy:** conditional `.technique-explainer` section/div; optional header and title; required native `.technique-explainer__steps`; repeated direct native `.technique-step` items; required content, name, and description; optional target-composed details, redundant visual number, and contextual media figure.

### Targets

- **Neutral Web:** conditional native section/div, `ol/li`, complete text, optional contextual media, named-container CSS, meaningful order, and zero R3 JavaScript.
- **Shopify:** planned until record source, editorial/safety review, section/block schema, order/limits, localization, media policy, and first consumer are approved.
- **Webflow / React / Angular:** preserve native ordered children and target-owned content/media lifecycle; keep workflow state separate.
- **Figma / native targets:** represent optional title, repeated ordered items, optional media, and adaptive composition; registered generic Figma nodes are not R3 visual approval.
