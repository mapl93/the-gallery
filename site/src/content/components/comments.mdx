## Overview

Comment Section is a fail-closed, finite discussion associated with surrounding content. It requires a visible contextual heading plus one non-null discussion slot, renders at most two visible thread levels, and delegates identity, permissions, moderation, sanitization, persistence, authoritative counts and mutation results to the target.

The default record order is oldest first. A target may compose canonical Select for another verified order and canonical numbered Pagination for a long discussion. The neutral component never sorts DOM records, loads infinitely or adopts Feed semantics.

## Usage Guidelines

<DoDont>
  <Do>Supply one authoritative oldest-first record set by default. If another verified order is offered, compose canonical Select and replace the complete projected set.</Do>
  <Dont>Do not sort the rendered DOM, infer order from timestamps, append an infinite Feed or treat count text as pagination truth.</Dont>
</DoDont>

<DoDont>
  <Do>Give every record an ordered reaction array containing stable id, complete localized accessible label, optional target icon/count, selected state and availability.</Do>
  <Dont>Do not add a `single | multiple` mode. An empty array removes reactions; after activation the target returns the complete authoritative array and may enforce its own independent or mutually exclusive policy.</Dont>
</DoDont>

<DoDont>
  <Do>Show Reply only when an authenticated target composer and moderation lifecycle exist.</Do>
  <Dont>Do not fabricate nesting or reactions in a flat provider such as Shopify, or let the neutral renderer claim posting success.</Dont>
</DoDont>

Fixture people, initials, dates, copy, count, reaction vocabulary/icons/counts, order choices, page window, Reply actions, composer labels and submit copy are evidence content—not defaults or public API.

## Accessibility

- Name the native `section` from its visible contextual heading; blank title or absent discussion composition omits the complete root.
- Use `ol.comments__thread > li.comments__item > article.comment`, with at most one `ol.comment__replies` under a top-level item. Do not rely on indentation alone.
- Name every comment article from visible author plus optional date. Use native `time[datetime]`, complete localized text and `dir="auto"` where the target direction is unknown.
- Flatten deeper provider replies in authoritative order and display a localized `.comment__reply-to` label naming the immediate parent.
- Hide redundant Avatar initials when adjacent visible author text already supplies identity.
- Render every reaction as a standalone native Toggle button with `aria-pressed`, native `disabled` and the supplied complete label. The optional icon/count never replaces that name.
- Do not wrap reactions in the exclusive `.toggle-group`: the target may preserve several independent selections or atomically return an exclusive array.
- Preserve canonical Select, Pagination, Button, Textarea and Empty State keyboard/focus/state contracts. Target result replacement, announcements and focus restoration remain external.
- Do not add `role="feed"` without the complete automatic loading, focus navigation, position/set-size and busy-state behavior required by APG.

## Responsive And Targets

The neutral shell has one intrinsic column and establishes an inline-size container. Metadata, actions, reactions and Pagination wrap; replies use logical container-relative indentation; complete localized content is never clamped. L11 owns no breakpoint, animation, request, storage or event listener.

Shopify is implemented by `sections/comments.liquid`. It reads published `article.comments`, reuses canonical Empty State and Pagination, and uses `{% form 'new_comment', article %}` with exact `comment[author]`, `comment[email]` and `comment[body]` names plus localized moderation/error/success feedback. Shopify's native model is flat, so the adapter intentionally emits neither reply controls nor reactions.
