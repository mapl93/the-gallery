## Overview

Popup presents a dismissible dialog surface with Default, Split, and Slide treatments. Email capture is not part of the accepted Popup API.

The primary Exhibit artwork starts visible. Its sibling trigger is hidden while the overlay is active, appears after dismissal, and can reopen the fixture. This staging and geometry are site-owned documentation behavior, not a Popup default or public property.

Default uses `.popup`; Split adds `.popup--split`; Slide adds `.popup--slide`. Canonical CSS currently recognizes `data-open` on `.popup-overlay` and on `.popup--slide`, but the public visibility surface remains unresolved.

## Usage Guidelines

<DoDont>
  <Do>Use Popup for a concise, focused message with a clear visible way to leave.</Do>
  <Dont>Do not add an email property or Input dependency until email-capture ownership is accepted.</Dont>
</DoDont>

The consuming target decides whether a use is modal or non-modal. It also owns visibility state, focus management, trigger timing, persistence, and dismissal behavior beyond this Exhibit fixture.

## Accessibility

- For modal use, apply `role="dialog"`, `aria-modal="true"`, and a programmatic name from the visible title.
- Move focus into a modal popup, contain Tab and Shift+Tab navigation, and restore focus to its trigger after dismissal.
- Provide a visible named dismiss button and support `Escape`.
- Respect reduced-motion preferences for overlay and slide transitions.
- Any target-composed form field must independently satisfy Input obligations; it does not become Popup anatomy.
