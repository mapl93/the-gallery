## Presentation

Title is required non-empty content. Icon, message, and one action are independent optional slots. The icon is decorative. The action composes canonical Button or Link; Empty State does not own its label, destination, event, state, or a local action style.

The artwork, copy, and action shown in Studio are preview fixtures, not component defaults.

The title class is independent of its native heading tag. The owning page, section, panel, or dialog must supply the contextually correct native `h1` through `h6`. Heading rank is host composition context, not a visual Studio control or target-agnostic property.

## Usage Guidelines

<DoDont>
  <Do>Explain what is empty and offer one clear next step when an action can resolve it.</Do>
  <Dont>Don't show Empty State while content is loading, or use it as a generic error without a truthful diagnosis.</Dont>
</DoDont>

- Replace the missing content area instead of leaving stale rows, controls, totals, or results visible beside the Empty State.
- Prefer concise, contextual copy. Omit the message or action when neither adds a useful next step.
- Use Link when the recovery action navigates and Button when it performs a command.
- Choose one primary action. Additional education, error recovery, permissions, filtering, and query state remain target composition.

## Accessibility

<Callout type="info">
  Empty State is for resolved empty content, not loading. Use Skeleton or Spinner while data is still pending.
</Callout>

- Use clear title text that identifies the empty state.
- Use a contextual native heading rank and keep the visible hierarchy meaningful. The title must never be empty.
- Make the optional canonical action keyboard accessible, descriptive, and semantically accurate as Link or Button.
- Keep the icon hidden from assistive technology because title text communicates the state. A meaningful illustration is not supported by the current narrow slot.
- Initial or static empty content needs no live role. If search, filtering, deletion, or another update dynamically produces a qualifying status message, announce it through a target-owned live region that already exists before the update.
- Do not move focus merely to announce absence, trap focus, or duplicate the visible title in every composed Empty State.

## Responsive And Targets

Block padding follows the semantic section rhythm, while inline padding is capped by the actual container so panels and narrow slots retain readable measure. Long localized title, message, and action content may wrap; the component adds no breakpoint, query parser, formatter, event, asset, or runtime.

Neutral Web provides only composition classes. Shopify requires a validated adapter-only `heading_tag`: main cart and 404 use H1, while the cart drawer uses H3 beneath its H2 dialog title. React, Angular, SwiftUI, and Compose must keep data lifecycle, announcements, focus, contextual heading markup, and action behavior in the target.

## Visual Customization

Studio and Exhibit expose independent block/inline padding, content gap, decorative icon size, title/message maximum widths, and semantic typography/colors. Inline padding keeps the existing 20% container cap; title/message widths use `ch`, which follows their own font metrics. Heading level and recovery behavior stay with the host. When adopting this version, a consumer that previously changed both insets through the section-gap alias should also set `--space-empty-state-padding-inline` to retain that override.
