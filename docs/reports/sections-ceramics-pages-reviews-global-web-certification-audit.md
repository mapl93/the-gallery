## Automated Evidence

The current `component-web-certification.md`, generated by
`npm run audit:components`, reports:

- 183 registry components and 183 automated gate passes.
- Zero structural gaps and zero neutral-web manifest drift.
- 183 Studio definitions covering all 793 reviewed semantic properties.
- One contract marked `stable`; Button is the only stable component. The other
  182 components, including all 55 in this scope, still require human review.

The current `component-preview-static-audit.md`, generated by
`npm run audit:previews:static`, reports 183 MDX files, 250 Preview blocks, 20
interactive previews, zero errors, and one warning.

The single warning is intentional: `.file-upload__input` is an absolutely
positioned, transparent native file input covering the drop zone. It retains
pointer handling so clicking the visible surface opens the native file chooser.
Adding `pointer-events: none` to satisfy the heuristic would remove that native
click path. The warning therefore remains documented rather than suppressed.

## Browser Evidence

The local docs site was tested at 1280px desktop and a verified 390px mobile
viewport. All 55 scoped components were opened in both Exhibit and Studio:

- 220 view combinations completed with the expected renderer present.
- Zero page-level horizontal overflows.
- Zero Studio-stage overflows.
- Zero broken images.

Interaction checks passed for Search Overlay close and reopen, Star Input value
selection, Coming Soon local signup, Commission Form local submission, and
Review Form local validation. These fixtures explicitly avoid network requests
and report that nothing was uploaded or submitted.

Browser QA found and closed four concrete presentation defects:

- Studio Tour media exceeded its mobile stage.
- Image with Text and Gallery Grid used viewport media queries inside a narrow
  Exhibit container.
- Featured Collection and Multicolumn retained desktop minimum tracks in the
  mobile Exhibit.
- Review active states and Page primary actions used editorial accent surfaces
  instead of the accepted primary action tokens.

The fixes use container-responsive layouts, bounded Studio fixtures, and the
same primary tokens as Button. Validation and the web adapter were rebuilt after
the source changes.

## Result And Residual Risk

These 55 components satisfy the current structural neutral-web pilot gates.
This report does not claim exhaustive assistive-technology, provider,
data-service, dark-theme, or target-adapter certification. Dark-theme coverage
was completed for Sections by its renderer audit; the remaining scoped groups
still require a dedicated human dark-theme pass because the docs UI does not
currently expose a theme switch that browser QA can operate.

Promotion to `stable` remains blocked on the human review required by ADR 0034
and on the applicable open product boundaries in `docs/OPEN-QUESTIONS.md`.
File Upload's transparent native input also retains a focused residual QA need:
its click, keyboard focus, drag-and-drop, and assistive-technology behavior must
be confirmed in supported browsers rather than inferred from the static audit.
