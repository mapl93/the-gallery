## Overview

Consent Manager is a controlled composition for presenting a target-authorized privacy decision. Its public slug remains `cookie-consent` only as a pre-v1 migration path; there is no second Cookie Consent implementation.

The neutral component owns a named, non-modal first layer; explicit Accept, Reject, and Customize requests; canonical Button and Link composition; and a canonical Modal boundary for detailed preferences. The target owns jurisdiction, legal copy, categories, current values, provider integration, persistence, processing gates, withdrawal, errors, and audit evidence.

## Composition

- Render the first layer in normal document flow. A target may place it in a fixed or sticky host only when that target owns safe-area, stacking, page reservation, and focus-not-obscured behavior.
- Provide a visible localized title, explanation, and real policy destination.
- Keep Accept, Reject, and Customize as explicit, comparably reachable native Button requests.
- Use the canonical Modal for detailed preferences. Do not create consent-specific overlay, focus containment, Escape, or restoration behavior.
- Supply current category records and values through canonical choice controls. Consent Manager does not define universal categories or defaults.
- Omit or natively hide the complete composition when authoritative target state closes it.

## Controlled State

- `open=false` means the first layer and preferences are absent from interaction; transform-only hiding is invalid.
- `preferencesOpen` projects the canonical Modal state. Customize, Close, Escape, and Save request target reconciliation.
- `busy` projects an in-flight target mutation with `aria-busy` and unavailable decision/save actions.
- `feedback` is an optional slot because pending, success, failure, retry, and their announcement semantics depend on a real provider result.

The component has no uncontrolled consent default. Closing, inactivity, scrolling, and continued use never imply consent.

## Public Properties

Content properties are `title`, `description`, `policyLabel`, and `policyHref`. Decision labels are `acceptLabel`, `rejectLabel`, and `customizeLabel`. Preferences use `preferencesTitle`, optional `preferencesDescription`, required `preferences`, `closePreferencesLabel`, and `saveLabel`. Controlled projection uses `open`, `preferencesOpen`, `busy`, and optional `feedback`.

These properties describe stable, cross-target semantics. Category identifiers, legal basis, provider errors, persistence records, cookies, storage keys, geography, processing flags, analytics, and audit data remain outside the component API.

## Accessibility

- The first layer is a named section, not a modal and not an alert.
- Canonical Buttons preserve keyboard activation, disabled state, focus indication, and readable labels.
- Canonical Link preserves real navigation and visible focus.
- Canonical Modal owns initial focus, contained Tab and Shift+Tab, Escape, visible close, inert-background integration, and logical focus restoration.
- Target-supplied categories use labeled canonical choice controls with current controlled values.
- Closed content is omitted or natively hidden, so no invisible policy link or action remains tabbable.
- A fixed target placement must separately prove that it does not obscure focused content.

## Target Translation

- **Neutral Web:** semantic HTML and canonical CSS composition; native click callbacks/handlers request target action; no provider, storage, network, or cookie runtime.
- **Shopify:** a future adapter must project `window.Shopify.customerPrivacy` state and `setTrackingConsent` results into this controlled profile. Copied CSS alone is not target readiness.
- **React/Angular:** thin controlled props and callbacks over the same content, request, and Modal boundaries.
- **Figma:** first-layer, busy, closed, and preferences-open visual states only; no compliance or persistence claim.
- **SwiftUI/Compose:** native privacy-service state and native modal/choice controls while preserving the same target ownership.

Human review must approve the first-layer hierarchy, equal-action treatment, density, wrapping, Modal presentation, and example fixture. The contract remains `pilot` until that review.
