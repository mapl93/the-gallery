## Presentation

`title` and `results` are required. `introduction` and the target-owned `filters` slot are optional. Results use native list semantics and create token-defined columns (one, two, or three initially) from the component width, but do not prescribe a result-card dependency.

The shared default fixture omits filters rather than presenting an incomplete interaction. ADR 0080 leaves single-select versus multi-select, selected-state semantics, filter-to-result and URL synchronization, empty/loading/error results, and announcements target-owned. `[aria-pressed="true"]` and `.is-active` remain visual hooks rather than a universal toggle-button decision.

All three result-density bands use public count tokens (1/2/3 initially).
The existing 27rem/44rem content-box queries select the active value for one
grid formula. Counts are positive integers bounded below by one, with no
neutral upper ceiling. Header rhythm, introduction measure (60ch), inset cap
and the existing optional-filter visual hooks are customizable too.

The default Studio fixture still omits filters. Their controls describe public
CSS hooks; exercising them requires a real target-owned filter composition.
No selection or result lifecycle is synthesized. A consumer choosing Artist
Card records explicitly installs Artist Card; no dependency is added here.

Copy-and-own consumers explicitly adopt CSS/tokens and metadata. This adds
visual controls without new semantic properties, data models or runtime.

## Usage Guidelines

<DoDont>
  <Do>Define selection semantics and result synchronization in the target before activating filters.</Do>
  <Dont>Do not infer single-select behavior from the selected visual hook.</Dont>
</DoDont>

- Keep result records in stable source order unless the target clearly communicates sorting.
- Provide an empty-result treatment and update announcements when the target implements filtering.
- Do not apply pressed, checked, or selected state only to obtain the visual treatment; it must match real target behavior.
- Compose result content without assuming Artist Card ownership.

## Accessibility

- Use a page-appropriate heading level for the Artist Index title.
- Give filter controls visible text, keyboard access, and focus indication when a target activates them.
- Choose and correctly implement one target-owned selection pattern before applying selected semantics.
- Keep the passive result layout as a native list; do not add grid/listbox roles or arrow-key behavior.
- Preserve logical result order and announce target-driven result changes and empty results where appropriate.

## References

**Dependencies:** None. Artist Card is not a dependency of the current result slot.

**Anatomy:** required `.artist-index` root, `.artist-index__header`, `.artist-index__heading`, native `.artist-index__grid` list, and repeated `.artist-index__item`; optional `.artist-index__intro`, `.artist-index__filters`, and `.artist-index__filter-btn`.
