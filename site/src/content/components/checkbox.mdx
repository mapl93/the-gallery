## Overview

Native binary choice with checked, indeterminate, disabled, required, form-value, validation, hover, and focus-visible behavior.

<Preview html={'<div class="tg-preview-frame tg-preview-frame--sm"><label class="checkbox"><input class="checkbox__input" type="checkbox" name="terms" value="accepted" /><span class="checkbox__label">Accept terms and conditions</span></label></div>'} label="Checkbox" />

## Presentation

Checkbox has one default size and four validation variants. Selection is a native state independent from validation: any variant may be unchecked, checked, or indeterminate.

| Property | Value | Web mapping |
| --- | --- | --- |
| `variant` | `default` | `.checkbox` |
| `variant` | `error` | `.checkbox--error` |
| `variant` | `success` | `.checkbox--success` |
| `variant` | `warning` | `.checkbox--warning` |
| `checked` | `true` | native `checked` |
| `indeterminate` | `true` | `data-indeterminate="true"` initializes native mixed state |
| `disabled` | `true` | native `disabled` |
| `required` | `true` | native `required` |

The generated Check and Minus indicators use accepted Lucide geometry without adding an icon-library dependency to the web adapter.

## Usage Guidelines

<DoDont>
  <Do>Use Checkbox for independent binary choices or for selecting multiple items from a set.</Do>
  <Dont>Do not use Checkbox when exactly one option must be chosen; use Radio instead.</Dont>
</DoDont>

<DoDont>
  <Do>Use indeterminate only to summarize a mixed group and let the next user action resolve it.</Do>
  <Dont>Do not treat indeterminate as a third submitted value; native form submission still depends on checked.</Dont>
</DoDont>

Use Field Wrapper for helper or validation feedback. Checkbox owns the visual variant and native state; Field Wrapper owns message layout and content.

## Accessibility

<Callout type="info">
  Checkbox keeps a native `input[type="checkbox"]`. Custom presentation does not replace its keyboard, form, required, disabled, or assistive-technology behavior.
</Callout>

- Wrap the native input and visible text in a `<label>`, or associate them using matching `for` and `id` attributes.
- Keep `name`, `value`, `checked`, `required`, and `disabled` on the native input.
- Space toggles the focused checkbox; clicking any part of the wrapping label toggles it.
- Use native `indeterminate` for mixed state. `data-indeterminate="true"` is the progressive initialization hook.
- Use `aria-invalid="true"` only for Error and connect external feedback with `aria-describedby`.
- Success and Warning do not expose invalid or alert semantics.
- Checked and indeterminate retain different visible indicators so selection does not rely on color.
- Forced-colors mode restores native checkbox appearance.
