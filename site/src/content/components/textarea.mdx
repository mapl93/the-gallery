## Overview

Native multi-line value-entry field that composes Input form semantics, validation, feedback, typography, spacing, focus, hover, and disabled behavior while exposing configurable resize direction and line bounds.

## Presentation

### Visual customization

The component's public tokens drive its rendered appearance. Studio exposes independent **Label gap** and **Message gap**, **Border width**, **Radius**, state-aware **Fill** and **Border** colors, padding, typography and icon controls where applicable. Focus width/offset, label weight, font family, bottom margin and disabled opacity are also editable. Exhibit's Specification section lists the same controls directly from contract and Studio metadata.

The two gaps default to 4 px but can differ. Their source paths are `component.input.labelGap` and `component.input.messageGap`; `component.input.borderWidth` owns the field border thickness. Edit canonical source defaults in the repository and regenerate targets, or override the public aliases in a consumer's theme. Studio edits are local previews. Changing border thickness or padding may change the field height; the shared 46 px baseline applies to defaults.


Textarea has one default size and the four shared field variants. The root uses the canonical Input modifier classes; `.textarea__field` adds native resize direction and configurable line bounds. Vertical and four minimum lines are the defaults, while the optional `data-resize`, `data-min-lines`, and `data-max-lines` attributes configure the remaining behavior.

Hover and focus preserve the active Error, Success, or Warning color family.
The shared Input layer also provides logical geometry, strengthened semantic boundaries, reduced-motion handling, and forced-colors focus behavior.

| Property | Value | Web mapping |
| --- | --- | --- |
| `variant` | `default` | `.input` |
| `variant` | `error` | `.input--error` |
| `variant` | `success` | `.input--success` |
| `variant` | `warning` | `.input--warning` |
| `size` | `default` | `.textarea__field` |
| `resize` | `vertical` | no attribute |
| `resize` | `horizontal` | `data-resize="horizontal"` |
| `resize` | `both` | `data-resize="both"` |
| `minLines` | `4` | `data-min-lines` when non-default |
| `maxLines` | no limit | `data-max-lines` when provided |

### Line bounds

`minLines` and `maxLines` use positive whole numbers. The shared progressive enhancer converts the attributes into pixel boundaries from the field's computed line height, padding, and borders. When `maxLines` is lower than `minLines`, the effective maximum is clamped to the minimum.

### Native form behavior

`name`, `required`, `readOnly`, `autocomplete`, `minLength`, and `maxLength` map directly to the native textarea. In static HTML, element text content establishes the initial value and the browser owns subsequent editing and reset behavior. Framework adapters may bind the live `value` property and native `input`/`change` events without adding a second value owner.

Character constraints are independent from visible-line bounds: `minLength`/`maxLength` constrain content, while `minLines`/`maxLines` constrain resize geometry.

## Usage Guidelines

<DoDont>
  <Do>Use Textarea when the expected value may require multiple lines or a longer explanation.</Do>
  <Dont>Do not use Textarea for compact single-line values such as names, email addresses, or codes.</Dont>
</DoDont>

<DoDont>
  <Do>Use Error for invalid content and Warning for content that needs attention but remains acceptable.</Do>
  <Dont>Do not communicate validation through border or text color alone.</Dont>
</DoDont>

Use Vertical for normal form flows, Horizontal when height must remain fixed, and Both only where the surrounding layout safely accommodates changes on both axes. Set line bounds only when the interface needs predictable minimum or maximum space.

## Accessibility

<Callout type="info">
  Textarea is a native form control. Input classes provide presentation without replacing its native value, keyboard, selection, or resize behavior.
</Callout>

- Associate every textarea with a visible `<label>` using matching `for` and `id` attributes.
- Connect supporting and validation messages with `aria-describedby`.
- Use `aria-invalid="true"` only for Error; Success and Warning do not expose invalid state.
- Use `role="alert"` only when an Error message is introduced dynamically and requires immediate announcement.
- Use native `disabled` for unavailable fields.
- Use `readOnly` when content must remain focusable, selectable, and submittable but cannot be edited.
- Keep `name`, `required`, `autocomplete`, `minlength`, and `maxlength` on the native textarea and communicate required status visibly.
- Preserve the native resize handle and choose a direction that does not hide adjacent content or validation feedback.
- Use positive whole line counts and keep `maxLines` greater than or equal to `minLines`.
- Keep the visible message descriptive so validation does not rely on color alone.
