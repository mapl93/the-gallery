## Overview

Native mutually exclusive choice with named-group selection, default and live checked ownership, form participation, validation, and resilient long-label layout.

## Presentation

Radio has one default size and four validation variants. Selection is a native state independent from validation, so any variant may be selected or unselected.

| Property | Value | Web mapping |
| --- | --- | --- |
| `variant` | `default` | `.radio` |
| `variant` | `error` | `.radio--error` |
| `variant` | `success` | `.radio--success` |
| `variant` | `warning` | `.radio--warning` |
| `checked` | `true` | native `checked` |
| `disabled` | `true` | native `disabled` |
| `required` | `true` | native `required` |

The `20px` control is aligned to the first line of a `24px` label. Selection is represented by a filled boundary with a centered surface cutout, so it remains recognizably a radio dot rather than a hollow ring. Hover preserves the active validation family, and focus uses the matching lighter `4px` outer ring with no gap.

Long or localized labels wrap within their container while the control remains aligned to the first line.

### Visual customization

Border width and selected-dot inset are public controls, with defaults of 1.5px and 4px. Increasing the inset makes the dot smaller; keep it below half the available control interior. Focus width/offset, label family and weight are editable shared roles. Control size and label gap retain their existing Input icon aliases for compatibility.

Borders and labels retain documented 60%/70%/55% contrast mixes. Circle shape, native mutual exclusion and arrow navigation remain implementation/behavior rules. See the generated visual controls and the required group in the [contact composition](/compositions/contact).

## Usage Guidelines

<DoDont>
  <Do>Use Radio when one and only one option may be selected from a visible set.</Do>
  <Dont>Do not use Radio for independent choices or multiple selection; use Checkbox instead.</Dont>
</DoDont>

<DoDont>
  <Do>Give every choice in one group the same native `name` and a distinct submitted `value`.</Do>
  <Dont>Do not visually group radios without a programmatic group name.</Dont>
</DoDont>

Use Fieldset and Legend to name the choice group. Radio owns visual validation and native ARIA on each input; Field Wrapper owns associated feedback content.

### State ownership

In static HTML, `checked` establishes default checkedness and the browser owns the live group value. Framework adapters may expose `checked` for controlled use or `defaultChecked` for uncontrolled use, but they must bind the same native input and must not add a mirrored hidden value.

Changing one radio dispatches native `input` and `change` events. Form reset restores the original checked member, and successful submission includes only the selected member's `name=value` pair.

## Accessibility

<Callout type="info">
  Radio keeps a native `input[type="radio"]`. Custom presentation does not replace its mutual exclusion, arrow-key navigation, form, required, disabled, or assistive-technology behavior.
</Callout>

- Use one shared `name` for each mutually exclusive group.
- Wrap related choices in `<fieldset>` and name the question with `<legend>`.
- Keep each visible choice label associated with its native input.
- Arrow keys move selection within a focused native group; Space selects the focused choice.
- Use `aria-invalid="true"` only for Error and connect external feedback with `aria-describedby`.
- Success and Warning do not expose invalid or alert semantics.
- A required group is valid when one enabled member with the shared `name` is selected; native invalidity does not imply Error styling until the consumer selects the Error variant.
- Forced-colors mode restores native radio appearance.
