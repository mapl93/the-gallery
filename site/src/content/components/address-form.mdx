## Overview

Address Form is a localized address profile of canonical Form. It composes target-owned canonical Input and Select fields with optional canonical actions, preserves native serialization, constraint validation, and explicit submit, and keeps its compact rows responsive to the component container.

## Presentation

`fields` is the required canonical Form section for a complete target-defined set of canonical Input and Select controls. Every successful control needs a visible label, unique ID, stable non-empty submission name, and the correct autocomplete purpose. Field inventory, values, requiredness, validation, and locale-specific order remain owned by those controls and the target address model. When multiple custom or server errors need an overview, the target may compose canonical Form error-summary markup before the affected fields and link it to their canonical messages.

`actions` is optional and uses the canonical Form action row. Submit remains explicit. Cancel is a target-owned navigation or close action with `type="button"` or native Link semantics; it never means reset. The repeated fields and intercepted action feedback in the artwork are docs fixtures, not a universal address schema or lifecycle. `.address-form__row` specializes canonical Form row layout for the compact U7 measure and does not create semantic grouping or a separate field API.

Address Form has no controlled/uncontrolled value state. Composed fields keep their own value strategy; the target owns create/edit mode, authentication, localized schema, validation response, protected mutation, cancellation, routing, focus recovery, and feedback. U7 formally depends on canonical Form under owner decision U7-A and ADR 0264.

## Usage Guidelines

<DoDont>
  <Do>Use stable submission names and correct native autocomplete purposes, then arrange fields for the destination locale.</Do>
  <Dont>Do not flatten field state, validation, address schema, or mutation lifecycle into Address Form properties.</Dont>
</DoDont>

- Ask only for fields required by the target and destination locale.
- Let Input and Select preserve their own names, values, autocomplete, requiredness, and default/error/success/warning semantics.
- Submit only through explicit native form submission; do not submit on field change, blur, or country selection.
- Keep action labels explicit about whether the address is created or updated.
- Map mutation user errors back to the affected canonical fields, add a useful linked Form error summary when needed, and reconcile target state only after its response.
- Treat Cancel as navigation or close composition; do not use `type="reset"` or claim that draft values were discarded.

## Accessibility

- Protect address editing behind the target authentication and authorization system.
- Preserve the native form boundary, successful-control names, required constraint validation, and explicit submit.
- Associate every field with a visible label and appropriate autocomplete value.
- Connect field-level help and validation messages with `aria-describedby`; identify errors in text.
- Move focus to the first invalid field or a useful error summary after failed custom/server validation.
- Preserve DOM, reading, serialization, and keyboard order when responsive rows collapse.
- Keep pending/success/failure and cancellation feedback outside U7, with deliberate target-owned focus after navigation, closure, or failed submission.
