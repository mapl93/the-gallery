# 0010. Neutral Web Token Target

Status: Accepted Initial Implementation

Date: 2026-05-23

## Context

The Gallery now has a DTCG-style token source, a source-token compiler, and a migration map that proves value parity against the legacy token files. The next step is to let one real target consume `tokens/source/` without replacing Shopify, Webflow, or Framer yet.

The lowest-risk target is neutral web CSS because Shopify, Webflow, Framer, React, Angular, and vanilla web targets all build on web foundations.

## Decision

The first real target generated from `tokens/source/` is:

```text
platforms/web/tokens.css
```

It is generated by:

```text
scripts/build-web-tokens.js
```

The output combines all source-token matrices into one CSS file:

```text
light/mobile
light/tablet
light/desktop
light/xl
dark/mobile
dark/tablet
dark/desktop
dark/xl
```

## Theme Behavior

`platforms/web/tokens.css` uses this theme strategy:

- `:root` receives light tokens by default.
- `[data-theme="light"]` forces light tokens.
- `@media (prefers-color-scheme: dark)` applies dark tokens when no manual root theme is set.
- `[data-theme="dark"]` forces dark tokens.

## Viewport Behavior

Responsive token overrides are emitted at:

```text
768px
1024px
1440px
```

These correspond to the current source viewport modes:

```text
mobile
tablet
desktop
xl
```

## Commands

```sh
npm run build:tokens:web
npm run validate:tokens:web
npm run validate:tokens:web-components
```

`build:tokens:web` runs the source-token build, source-build parity validation, web CSS generation, web CSS validation, and component CSS compatibility validation.

## Consequences

- The neutral web target is the first concrete consumer of `tokens/source/`.
- The target exposes canonical `--tg-*` variables plus current public component-token compatibility aliases. See `docs/decisions/0011-web-token-compatibility-aliases.md`.
- Shopify now consumes this target through a thin wrapper. Webflow and Framer remain on the legacy token build until they receive wrappers or source-token outputs.
- Target switching can now be discussed in terms of adapting from `platforms/web/tokens.css`, not jumping straight from legacy to a platform-specific target.
- The generated CSS file is intentionally tracked as a target artifact, unlike the ignored comparison sandbox under `tokens/source/build/`.
