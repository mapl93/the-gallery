## Overview

Date Picker combines an editable local-date field with an explicit calendar trigger. The native text input remains the value, validation, and form-submission owner; the calendar adds spatial selection without converting the date through a timezone.

## Presentation

The canonical fixture uses the stable `YYYY-MM-DD` edit format, a non-modal calendar dialog, and one selected day. The enhancer builds the complete six-week grid from this authored anatomy, so Exhibit and Studio exercise the same states and class contract.

## Usage Guidelines

<DoDont>
  <Do>Use Date Picker when calendar context helps users choose one day and preserve a visible format hint for direct entry.</Do>
  <Dont>Don't use this single-date contract for ranges, date-and-time values, or locale-specific edit formats without a separate accepted decision.</Dont>
</DoDont>

## Behavior

- Direct editing and calendar selection share one native text value serialized as `YYYY-MM-DD`.
- The input opens the calendar with `ArrowDown`; the explicit trigger is independently keyboard reachable.
- Day focus is roving: arrow keys move by day or week, `Home`/`End` move within the week, `PageUp`/`PageDown` move by month, and adding `Shift` moves by year.
- `Enter` or `Space` selects the focused date, emits native `input` followed by `change`, closes the dialog, and returns focus to the input.
- `Escape`, outside pointer activation, or focus leaving the component closes the non-modal dialog.
- `min` and `max` are inclusive ISO bounds. Unavailable days and month controls are disabled and skipped.
- Native form reset restores the authored input value and closes the calendar.

## Accessibility

- Keep a visible `<label>` associated with the editable input; a placeholder is never its accessible name.
- Expose the input as `role="combobox"` with `aria-haspopup="dialog"`, `aria-autocomplete="none"`, `aria-expanded`, and `aria-controls`.
- Name the calendar dialog and associate its grid with the live month heading.
- Render explicit week rows and full weekday/date names while keeping only one enabled day at `tabindex="0"`.
- Expose today with `aria-current="date"`, selection with `aria-selected`, and unavailability through the native `disabled` state.
- Keep the trigger enabled only while the input is editable; disabled and read-only values remain native form states.

## Composition and targets

The base source owns CSS and progressive behavior without a framework dependency. Web consumes the native input, explicit button, and generated grid directly. Shopify should render the same form owner and enhancement hooks in Liquid, while React and future targets map controlled `value`/`open` state onto the same event and focus contract. Range selection, localized edit formats, first-weekday policy, multiple months, and time selection remain separate decisions.
