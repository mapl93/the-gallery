# 0011. Web Token Compatibility Aliases

Status: Accepted Initial Implementation

Date: 2026-05-23

## Context

The neutral web target now generates canonical The Gallery CSS variables from `tokens/source/` using the `--tg-*` namespace.

The existing component CSS under `components/css/` predates that target and already consumes a public web token API such as:

```text
--color-*
--typo-*
--space-*
--radius-*
--shadow-*
--transition-*
--easing-*
--z-*
```

Replacing those names immediately would create unnecessary migration risk. The first web target should prove source-token compatibility with existing components before Shopify, Webflow, React, or other targets switch over.

## Decision

ADR 0311 refines the emission policy: complete bases per theme scope, then only
changed expressions at each viewport. The two namespaces remain:

`platforms/web/tokens.css` exposes:

1. Canonical source-derived variables in the `--tg-*` namespace.
2. Public compatibility aliases for the current component CSS API.

Compatibility aliases are generated by `scripts/build-web-tokens.js`.

Examples:

```css
--color-surface-primary: var(--tg-color-surface-primary);
--typo-body-size: var(--tg-typography-body-default-size);
--typo-button-size: var(--tg-component-button-font-size);
--space-button-padding-x: var(--tg-component-button-padding-x);
```

These aliases are target compatibility, not canonical token source. New source-token work should still happen in `tokens/source/`.

## Validation

The compatibility contract is executable:

```sh
npm run validate:tokens:web-components
```

This command scans `components/css/**/*.css`, collects every public `var(--...)` reference, ignores component-private `--_` variables, and verifies that `platforms/web/tokens.css` defines each public token.

`npm run build:tokens:web` now runs this validation after generating `platforms/web/tokens.css`.

## Consequences

- Existing component CSS can consume the neutral web token target without a mass rename.
- The source of truth remains `tokens/source/`; aliases are emitted output policy for the web target.
- Private component variables such as `--_btn-bg` remain component-local implementation details and are not part of the target token API.
- Future target adapters can choose whether to expose the same compatibility aliases, a target-native naming layer, or both.

## Follow-Up Work

- Apply the same wrapper pattern to Webflow when it switches to the source-token architecture.
- Add explicit source tokens for input layout/color if the input contract graduates from compatibility aliases into canonical component tokens.
- Use the same validator pattern when React, Angular, or other web adapters start consuming the neutral web target.
