## Overview

Immediate binary on/off setting backed by one native checkbox with switch semantics, stable visible labeling, form participation, validation, and three visual sizes.

## Presentation

Switch supports `default`, `error`, `success`, and `warning` validation families independently of size and checked state. The off state retains a surface track with a visible boundary; the on state fills the track. Semantic boundaries and active surfaces are contrast-reinforced while focus uses the matching lighter `4px` outer ring.

### Visual customization

Each existing size exposes track width, track height and thumb size. Default is 44/24/18px, Small 36/20/14px and Large 52/28/22px. Border width and thumb inset default to 1px and 2px. The inset is inline only. Keep track width large enough for the thumb, two borders and two insets; track height must fit the thumb and two borders. Checked placement follows the actual track interior and mirrors in RTL.

Focus dimensions, family/weight, off surface and hover border are editable along with the existing gap, radius, thumb shadow, colors, opacity and motion roles. Borders and labels retain documented 60%/70%/55% contrast mixes. The hidden native input, positioning, continuous borders and forced-color system colors remain implementation details.

The [contact composition](/compositions/contact) uses Switch to immediately show visit information. Deferred request choices use Checkbox and Radio.

## Usage Guidelines

<DoDont>
  <Do>Use Switch for a binary setting whose effect is applied immediately.</Do>
  <Dont>Do not use Switch for choosing one item from a group, submitting a deferred form answer, or representing mixed state.</Dont>
</DoDont>

<DoDont>
  <Do>Keep the visible label stable while checkedness communicates on or off.</Do>
  <Dont>Do not change the accessible name from “Enable…” to “Disable…” when the setting toggles.</Dont>
</DoDont>

Persistence, optimistic pending treatment, retry, and rollback belong to the consuming target. The base component owns only the immediate native state and its presentation. Use Checkbox when the choice may be indeterminate or is committed later with a form.

### State ownership

In static HTML, `checked` establishes default checkedness and the browser owns the live state. Framework adapters may expose `checked` for controlled use or `defaultChecked` for uncontrolled use, but must bind the same native input and must not synchronize a second hidden checkbox.

The checked switch submits its `name=value` pair; the off switch contributes no value. Native form reset restores default checkedness. The default submitted value is `on` unless the consumer supplies `value`.

## Accessibility

<Callout type="info">
  Switch requires `role="switch"` on its native checkbox. Native `checked` remains the sole visual, form, and accessibility state; a separately managed `aria-checked` is unnecessary.
</Callout>

- Provide a stable visible label associated through the wrapping `<label>`.
- Support Space, click, native `input`, and native `change` through the checkbox.
- Keep `checked`, `disabled`, `required`, `name`, and submitted `value` on the native input.
- A required switch is invalid while off; native invalidity does not imply Error styling until the consumer selects the Error variant.
- Use `aria-invalid="true"` only for Error and connect static feedback with `aria-describedby`. Static preview feedback is not an alert.
- Do not expose indeterminate or mixed state.
- Reduced-motion mode removes thumb and track transitions; forced-colors mode uses system colors without hiding checkedness, focus, or disabled state.
