## Usage Guidelines

<DoDont>
  <Do>Use Fieldset when controls form one meaningful choice or information group.</Do>
  <Dont>Don't use Fieldset only to draw a decorative border.</Dont>
</DoDont>

## Accessibility

- Preserve native `<fieldset>` and `<legend>` elements.
- Keep the legend visible and concise.
- Associate optional group descriptions with `aria-describedby`.
- Use native `disabled` when the complete group is unavailable.
- Keep controls out of the first legend unless they should remain enabled when the fieldset is disabled.
- Let canonical descendants own names, values, validity, events, and reset.

## References

### Visual customization

Inner padding, border width, legend side padding and legend weight are public
component decisions. Description gap and Control gap have separate Compact
controls for groups whose inner container is at most 320px wide. These preserve
the existing 16/12px description and 12/8px control defaults; they respond to the
actual group width even on a large screen.

Studio exposes the existing shared border/text colors, required marker, radius,
font family, legend/description typography and disabled opacity. The marker
appears when the group contains required native Radio controls; requiredness
remains the child's semantic decision. Fieldset stays transparent, with no shadow
or exterior margin. Native legend layout, the query threshold and disabled
propagation remain structural behavior. Group feedback can be composed inside
`.fieldset__content` so it shares the controlled vertical flow; associate its id
with the affected controls.
