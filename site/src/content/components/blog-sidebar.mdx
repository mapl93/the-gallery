## Overview

Blog Sidebar is a complementary-content container composed from repeatable target-owned sections. Sections may contain headings, destination lists, tags, or a target-provided search composition without creating separate root APIs for each content type.

The component has one stacked presentation. `.blog-sidebar__section` repeats inside the root; list content uses `.blog-sidebar__list`, `.blog-sidebar__list-item`, and `.blog-sidebar__link`; tag-cloud content uses `.tag-cloud` and `.tag-cloud__item`.

## Usage Guidelines

<DoDont>
  <Do>Group each complementary topic under a semantic section heading.</Do>
  <Dont>Do not infer separate search, category, recent-post, or tag properties from the fixture.</Dont>
</DoDont>

The target owns the section inventory and content. Whether Blog Sidebar composes the canonical Input and Tag components or owns independent search and tag APIs remains unresolved; the preview therefore does not introduce a search field or apply the `.tag` class.

## Accessibility

- Use an `aside` or complementary landmark only when the content supplements the main article or blog listing.
- Give the landmark a useful accessible name when the page contains more than one complementary region.
- Use semantic headings and list markup for grouped destinations.
- Preserve visible keyboard focus and touch-sized links and tags.
- Any composed search field must retain its owning field label, validation, and submission semantics.
