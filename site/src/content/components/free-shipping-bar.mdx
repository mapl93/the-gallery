## Overview

Free Shipping Bar combines one complete target-owned shipping message with the determinate Bar profile of canonical Progress. The target owns the qualifying amount, threshold, localized copy, eligibility, cart updates, and announcements.

## Presentation

`message` supplies one required complete below-threshold or achieved statement. `accessibleLabel` independently names the canonical progressbar, and optional `valueText` gives assistive technology a localized interpretation when raw money-like values would otherwise be announced only as a percentage.

`value` and `max` are required controlled target inputs with contract defaults of `0` and `100`. The implementation fixes the minimum at zero, requires a finite positive `max`, clamps the visual and accessible current value together, and derives `.shipping-bar--achieved` when the current value reaches the threshold. There is no independent achieved property.

## Usage Guidelines

<DoDont>
  <Do>Supply the message, value, max, and value text from the same authoritative eligibility calculation.</Do>
  <Dont>Do not infer free-shipping eligibility from fill width or choose a subtotal policy inside the component.</Dont>
</DoDont>

- Replace the remaining-amount message with an explicit achieved message when the authoritative threshold is reached.
- Format currency and describe exceptional eligibility rules in the commerce target.
- Keep the component passive; place it where the cart target can update it without giving K5 store or request ownership.
- Omit invalid composition rather than rendering a blank message/name or a non-positive threshold.
- Use the canonical Progress component for track, bar, range, reduced-motion, and forced-colors behavior.

## Accessibility

- Give the canonical progressbar a concise localized accessible name through `accessibleLabel`.
- Synchronize `aria-valuenow`, `aria-valuemax`, optional `aria-valuetext`, and fill width from the same clamped range.
- Use visible text to distinguish remaining and achieved states; width, color, and emphasis are supporting cues only.
- Do not make the root focusable, a landmark, or a live region.
- Announce one meaningful authoritative eligibility transition from the surrounding cart status policy rather than every amount update.
