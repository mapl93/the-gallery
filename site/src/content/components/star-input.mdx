## Overview

Interactive native radio group for choosing one integer rating from one through five. Star Input owns value entry; read-only contexts use Star Rating instead.

## Presentation

The root is a native fieldset with a visible legend. A dedicated choices row keeps native DOM, visual, and keyboard order ascending from `1` through `5`; CSS direction is not used to reorder the radios. Every touch-sized label contains localized text for its native radio and one decorative star. Empty stars remain outlines, while the chosen value and lower values are filled.

`default`, `error`, `success`, and `warning` are validation variants independent from the checked rating. Web maps them to the default root, `.star-input--error`, `.star-input--success`, and `.star-input--warning`. Each family covers the legend, star outlines and fills, hover, and focus ring. Error sets `aria-invalid="true"`; Success and Warning do not. All three require visible associated feedback through `describedBy`, so validation never depends on color alone.

The selected `value` is an integer from `1` through `5`. `required` maps to the named radio group, while `disabled` uses the native fieldset state and disables every descendant choice. Pointer preview never removes the checked value.

## Usage Guidelines

<DoDont>
  <Do>Use one Star Input for one clearly labelled rating question inside a native form.</Do>
  <Dont>Do not replace the radios with click-only stars, reverse their order with CSS, or reuse Star Input for passive display.</Dont>
</DoDont>

The containing form owns supporting and validation messages, submission, persistence, moderation, and provider normalization. Static HTML should establish an optional initial choice with `checked` and then let the browser own live state. Framework adapters may instead control one group `value` and respond to `change`; they must not control five independent booleans.

## Accessibility

<Callout type="info">
  Native radios retain arrow-key movement, validation, reset, focus, and form-submission behavior.
</Callout>

- Use a visible legend or an equivalent programmatic group label.
- Give every radio localized text such as `1 star` or `5 stars`; the decorative star is not its accessible name.
- Keep every radio on the same native `name` and in ascending source order.
- Project `:focus-visible` from the radio onto its touch-sized label without removing the radio from the focus order.
- Associate supporting or validation feedback through `aria-describedby` on the group.
- Use `aria-invalid` only for Error, and pair Error, Success, and Warning with visible text.
- Use native `required` and fieldset `disabled` states rather than visual-only substitutes.

## Target Translation

- Neutral Web uses a native `fieldset`, `legend`, five named radios, visible-label text and decorative SVG or glyph indicators with no component JavaScript.
- Shopify may render the same native markup, but review-provider submission, persistence and localization remain target-owned; generated Reviews CSS alone does not establish a provider adapter.
- React and Angular choose one controlled group value plus `change`, or an uncontrolled initial value; form reset behavior must stay explicit.
- Figma represents the four validation families and one-through-five choice states, but the registered references are generic Studio frames rather than approved Star Input artwork.
- SwiftUI and Compose use native exclusive selection and expose one labelled group with five localized choices.
